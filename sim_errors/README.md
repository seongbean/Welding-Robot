# 모재 오차 시뮬레이션 (sim_errors)

Isaac Sim에서 모재 오차를 용접 전·중·후로 나눠 분포로 주입하고, 실제 경로를 아는 규칙 전문가가 에피소드를 만들며 매 주기 정답(보정값)을 기록한다. 설계 근거와 범위는 Claude Doc "모재 오차 모델링 계획"에 있다.

| 파일 | 하는 일 |
| --- | --- |
| `config/part_errors.yaml` | 오차 분포, 센서, 규칙 전문가 설정. 기본 섹션 = T 필릿(공통값), `families.<군>` = 시편군별로 바꿀 값. 범위는 가정치이며 실측하면 이 파일만 고친다 |
| `part_errors.py` | 시나리오 샘플링, 실제·추정 경로, 정답, 모재 메시 변형, 이음매 단면 센서(코드 이름 `laser`, 실기에서는 손목 depth 카메라 단면, 판 면 평면 맞춤), 다음 패스 (numpy만 사용) |
| `resense.py` | 기록의 단면 열만 지금 센서 모델로 다시 계산 (Isaac 재실행 없이) |
| `expert.py` | 규칙 전문가: 접근 → 하강 → 용접(위빙) → 후퇴 토치 목표와 정답. 용접 구간만 모드, 직선 모드, 시작 어긋남, 실행 섭동 |
| `make_scenarios.py` | 시나리오 JSON N개 생성과 정답 크기 분포 요약, 오차별 단독 검증 시나리오(`--single`), 학습용 묶음(`--batch`) |
| `episode.py` | 기록(.npz) 저장 공통 부분, Isaac 없이 도는 운동학 에피소드(완벽 추종 가정) |
| `check_episode.py` | 에피소드 기록(.npz) 점검 8항목과 그래프 |
| `../sim_bridge/expert_to_sim.py` | 규칙 전문가 → opti3 IK → Isaac Sim, 에피소드 하나 기록(.npz) |
| `../sim_bridge/run_batch.py` | 묶음 일괄 실행, 에피소드별 자동 점검, 묶음 통계(`batch_report.json`) |
| `../sim_bridge/isaac_opti3_receiver.py` | Isaac Sim에 모재를 만들고 아크 진행도에 맞춰 변형을 그림. 패킷으로 시나리오 교체·바로 놓기 |
| `../learning/` | 묶음 → LeRobotDataset 변환, MLP/GRU 행동 복제, 보정 0 대비 평가 ([learning/README.md](../learning/README.md)) |

## 실행 순서

저장소 루트에서, `conda activate weld` 환경 기준.

1. 분포 확인: `python -m sim_errors.make_scenarios --n 500 --summary-only`
2. 시나리오 생성: `python -m sim_errors.make_scenarios --n 20 --out scenarios` (다층 용접은 `--passes 3`)
3. Isaac Sim (터미널 1):
   ```bat
   C:\isaacsim\python.bat sim_bridge\isaac_opti3_receiver.py --usd C:\...\posco_torch.usd --scenario scenarios\part0000_pass0.json
   ```
4. 규칙 전문가 (터미널 2):
   ```bat
   python sim_bridge\expert_to_sim.py --scenario scenarios\part0000_pass0.json --follower-urdf C:\workspace\indy-ros2-jazzy\indy_description\urdf_files\opti3.urdf
   ```
   시작 자세의 토치 팁 근처에 모재를 자동 배치하고, 이음매 전체에 IK가 닿는지 확인한 뒤 시작한다. 끝나면 `episodes/part0000_pass0.npz`에 기록한다.

5. 기록 점검: `python -m sim_errors.check_episode episodes\part0000_pass0.npz` (그래프는 `conda install matplotlib` 후 같은 폴더에 .png)

Isaac Sim 화면에서 빨간 선이 실제 이음매, 파란 선이 추정 경로다. 두 선의 차이가 정답이고, 토치는 빨간 선을 따라간다.

## 학습용 묶음 일괄 생성

에피소드 생성 사양의 묶음(깨끗함 30, 단독 65(코너 필릿 70), 혼합 205, 가혹 30)을 만든다. 모든 에피소드는 용접 구간만 담고,
로봇을 이음매 시작점 + 시작 어긋남(좌우·높이 ±2 mm, 작업각·진행각 ±2°) 자세에 바로 놓고 시작한다.
직선/위빙 모드는 에피소드 시작 때 정해 끝까지 고정하고 묶음마다 반반이다(직선 = 위빙 0, 속도 규칙만).
혼합 묶음의 절반에는 실행 섭동(좌우·높이 σ 0.5 mm, 각도 σ 1°, 0.5–2초 반 코사인)을 넣고 정답은 섭동 없는 값으로 둔다. 토치 자세를 정책 입력에서 뺀 뒤로는 섭동이 정책 관측을 바꾸지 않아 학습 효과가 없다(learning/README.md "수량·섭동 비교"). Isaac 추종 상태를 다양하게 하려고 그대로 둔다.
개수·비율·어긋남·섭동은 `config/part_errors.yaml`의 `episode` 섹션.

1. 시나리오: `python -m sim_errors.make_scenarios --batch --scale 0.2 --out batches/t_small` (1/5 수량 66개. 전체는 `--scale` 빼기)
2. Isaac Sim (터미널 1, 한 번만 띄움. `--scenario` 없이):
   ```bat
   C:\isaacsim\python.bat sim_bridge\isaac_opti3_receiver.py --usd C:\...\posco_torch.usd --lockstep
   ```
3. 일괄 실행 (터미널 2):
   ```bat
   python sim_bridge\run_batch.py batches\t_small --out episodes\t_small --follower-urdf C:\workspace\indy-ros2-jazzy\indy_description\urdf_files\opti3.urdf
   ```
   중단해도 같은 명령으로 이어서 만든다(있는 .npz는 건너뜀). 끝나면 강도별 통계와 `episodes\t_small\batch_report.json`.
   점검에 실패한 에피소드는 보고서에 이유가 남고 학습 변환에서 빠진다. 끝나지 않은 실행은 `*.failed.npz`.
4. Isaac 없이 흐름만 시험: `python sim_bridge/run_batch.py batches/t_small --out episodes/t_small_kin --kinematic --jobs 4`
5. Isaac을 띄우기 전 도달 점검: `python sim_bridge\run_batch.py batches\t_small --out reach --reach-only --follower-urdf ...\opti3.urdf`
   시나리오마다 자동 배치 후 이음매 41점과 시작 자세의 opti3 IK만 풀어 본다(Isaac 불필요, 수백 개에 몇 분).
   최대 IK 오차, 이웃 점 사이 관절 최대 변화(0.3 rad 이상이면 손목 뒤집힘으로 실패), 리밋 여유, 시편군별 관절 범위를
   찍고 `reach\reach_report.json`에 남긴다. 여기서 실패한 시나리오는 Isaac에서도 `reach`로 끝난다.
   시작 자세는 실제 실행과 같은 방법으로 고른다: 이음매 시작점 IK를 시드 41개로 풀고, 이음매를 따라갔을 때 관절 변화가 0.2 rad 미만인
   해 중 시작 자세에 가장 가까운 것 (`expert_to_sim.seam_path_q`). Isaac 배치는 `expert.isaac_nominal` = 자동 배치 + 시편군별 `ISAAC_SHIFT`.
   필릿은 토치가 45° 기울어 팁 바로 아래에 두면 플랜지가 베이스 축 근처(어깨 특이점)에 와서, +X 0.2 m, -Z 0.05 m 옮긴다
   (실제 opti3.urdf로 네 군 1/5 묶음 268개 모두 통과, 41점 사이 관절 최대 변화 T 0.10, 코너 0.10, V홈 0.04, 파이프 0.14 rad).

receiver 쪽 동작: 패킷의 `scene.scenario`가 바뀌면 모재를 다시 만들고, `reset_q`가 오면 로봇을 그 관절 자세로 순간 이동시킨다.
답장의 시뮬 시각(`t`)으로 전문가를 한 주기씩 진행하므로, Isaac이 멈추면 전문가도 멈춘다(single_place에서 0.34초 끊김으로 생긴
4.8 mm 오차 원인). `--lockstep`이면 receiver가 전문가의 응답을 받은 뒤 다음 물리 스텝을 밟아, `--headless`와 같이 쓸 때
실시간보다 빠르다. 물리 주기는 `--physics-hz`(기본 60, 이전과 같음)이고 전문가 주기도 같아진다.

## 시편군 (T 필릿, ㄱ자 코너 필릿, 맞대기 V홈, 파이프 원주)

`--family`로 고른다 (`make_scenarios --batch --family fillet_corner --out batches/corner`, `--family butt_v`, `--family pipe_girth`). 기본은 T 필릿(`fillet_t`).
config 기본 섹션이 T 필릿이자 공통값이고, `families.<군>`에는 바꿀 값만 쓴다 (`part_errors.family_cfg`). 맞대기와 파이프는 모양이 달라 `geometry`를 통째로 바꾼다.

| | T 필릿 `fillet_t` | ㄱ자 코너 필릿 `fillet_corner` | 맞대기 V홈 `butt_v` | 파이프 원주 `pipe_girth` |
| --- | --- | --- | --- | --- |
| 모재 | 바닥 판이 웹 양쪽으로 (폭 200, 두께 10), 웹 높이 100 · 두께 10, 길이 300 | 웹이 바닥 판 끝 위에 바깥 면을 맞춰 섬. 바닥 판은 토치 쪽 날개 180만 (두께 18), 웹 180 · 18, 길이 300 | 두 판(폭 150씩, 두께 12)이 같은 평면에 눕고 사이에 V홈. 개선 30°(홈 60°), 루트 면 1.5, 길이 300. 아래보기 루트 패스 | 12인치 관(바깥지름 323.9, 두께 12) 두 개를 축을 눕혀 맞댐. V홈 단면은 맞대기와 같고(개선 30°, 루트 면 1.5), 꼭대기 ±50° 원호만 용접(루트 반지름 151.45, 호 길이 264). 루트 패스 |
| 이음매 좌표계 z (토치 방향의 반대) | 두 판 면 법선 이등분 (45°) | 같음 | 두 개선 면 법선 이등분 (명목 = 위) | 같음 (명목 = 바깥 반지름 방향, 호를 따라 100° 돈다) |
| 루트 틈새 | 0–2 mm | 같음 | 1–3 mm (틈새를 두고 조립) | 2–4 mm (사양값) |
| 웹 직각도 (조립 때 웹 기울기) | 없음 | ±2° (작업각에는 절반이 보임, 아크와 무관하게 처음부터) | 없음 | 없음 |
| 단차 (오른쪽 판이 더 높은 양) | 없음 | 없음 | ±1 mm (정답 높이 = 절반) | ±0.8 mm 일정 + 두 관 진원도 차이 (둘레를 따라 변함) |
| 웹 기울어짐 열변형 (`web_tilt`) | ±1° | ±2° | 좌우 판 각변형 차이 ±1° (작업각 = 절반) | 같음 |
| 바닥 판 각변형 (`base_angle`) | 0.5–2° | 0.5–2.5° | 양쪽 판이 같이 들림 0.5–2.5° (이등분선 그대로, 정답 거의 0) | 같음 0.5–2° |
| 웹 직진도 (`web_bow`) | 2 mm/m | 2.5 mm/m | 이음선 좌우 직진도 2 mm/m | 이음선 축 방향 흔들림 2 mm/m |
| 진원도 (관마다 반지름 편차, cos 2ψ) | 없음 | 없음 | 없음 | ±1 mm, 위상 랜덤 (왼쪽 관 = 높이, 두 관 차이 = 단차) |
| 틈새 닫힘 | 0–1 mm | 같음 | 0–1.5 mm (가로 수축) | 0–1.5 mm |

| 묶음 파일 이름 | `mixed_0001.json` | `corner_mixed_0001.json` (군마다 다른 난수) | `butt_mixed_0001.json` | `pipe_mixed_0001.json` |

코너 수치는 모두 가정치다(웹 뒤를 받치는 판이 없고 날개가 한쪽뿐이라 T보다 웹이 더 기운다고 봄). 안쪽 모서리 필릿이라
이음매·정답·단면 센서 식은 T와 같다. 그래서 오차별 단독 검증의 기대 정답 표도 공통 13종은 T와 같고, 웹 직각도만 새로 생긴다.
poscoenc 시편의 선택 V홈은 아직 넣지 않았다. 여러 군 에피소드는 한 폴더에 섞거나 `to_lerobot`에 폴더 여러 개를 주면 된다
([learning/README.md](../learning/README.md) "시편군").

맞대기 V홈 수치도 모두 가정치다(poscoenc에 평판 맞대기 시편이 없어 흔한 값으로, 두께는 관 시편과 같은 12 mm). 시나리오 키 이름은
필릿 것을 그대로 쓰고 뜻만 바꿔 읽는다(위 표 괄호). 맞대기에서 다른 점:
- 모재 좌표계 원점 = 루트 가운데(루트 면 윗높이), y = 오른쪽 판 쪽, z = 위. `BASE` = 왼쪽 판, `WEB` = 오른쪽 판.
- 정답 점 = 두 루트 끝의 가운데 (단차가 있으면 높이 절반). 토치는 이등분선(위) 쪽에서 standoff만큼, 미는 각 10°.
- 단면 센서는 두 개선 면에 평면을 맞춘다(루트 끝에서 면을 따라 최대 15 mm, 면 길이 12.1 mm를 넘지 않음). 두 면의 교선은
  틈새가 있으면 루트보다 `틈새/2/tan(개선각)` 아래에 있으므로, 잰 틈새와 두 면 법선으로 잰 개선각으로 루트 높이까지 올린다.
  틈새 노이즈(σ 0.1 mm)가 여기서 높이 노이즈 약 0.09 mm가 된다(필릿은 0.04 mm).
- 단차 h가 있으면 두 개선 면 교선이 옆으로 밀려 좌우가 `-h·tan(개선각)/2`(단차 1 mm면 0.29 mm) 틀어진다. 그래서 센서가 홈 양옆
  판 윗면(홈 위 모서리에서 바깥으로 15 mm)의 점 높이 평균 차로 단차를 재서 되돌린다. 처음에는 이 보정이 없었는데, 그러면 V홈 데이터에서
  잰 좌우와 정답 좌우가 정책이 모르는 값만큼 어긋나 공용 MLP의 필릿 좌우까지 나빠졌다(T 0.16 → 0.21 mm). 단차를 끈 대조 실험에서
  원래대로 돌아와 원인을 확인했다([learning/README.md](../learning/README.md) "맞대기 V홈 한 바퀴").
- 다층(채움·덮개 패스)의 목표 높이 변화는 다루지 않는다. 루트 패스만이다.

파이프 원주는 맞대기 V홈을 관 둘레로 감은 것이다. 수치는 모두 가정치다(12인치 관, API 1104에서 흔한 개선; poscoenc 관 시편은
지름 700에 틈새 11.5 mm 시연값이라 쓰지 않음). 포지셔너가 없으니 관은 고정하고 꼭대기를 가운데로 한 ±50°만 용접한다고 봤다(아래보기에서 비스듬까지).
- 맞대기 식을 평평한 좌표(이음매 방향 u = 루트 반지름에서 잰 호 길이, 축 v, 반지름 방향 w)에서 그대로 계산한 뒤 관 둘레로 감는다(`_wrap_pts`, `_wrap_vec`).
  모재 좌표계 원점 = 이음매 평면의 관 축, y = 축(오른쪽 관 쪽), z = 위. 명목 이음매 = r(sin ψ, 0, cos ψ), ψ = (s − 0.5)·100°, 이음매 좌표계 = Ry(ψ)
  (`PartErrorModel.nominal`). 추정 경로도 같은 호를 쓰므로 정답은 맞대기와 같은 뜻(좌우 = 축 방향, 높이 = 반지름 방향)이다.
- 파이프에만 있는 오차는 진원도다. 관마다 반지름 편차 δ·cos 2(ψ − 위상)을 뽑고, 왼쪽 관 것은 높이(`base_height`), 두 관 차이는 둘레를 따라 변하는 단차가 된다.
  단면 센서는 판 윗면 높이 차로 그 자리의 단차를 재므로 맞대기와 같은 방식으로 좌우가 치우치지 않는다.
- **곡률 보정:** 단면 패치(이음매 방향 ±5 mm)의 점이 호를 따라 휘어, 맞춘 평면이 패치 가운데 루트보다 평균 a²/(2r) = 0.033 mm 안쪽에 놓인다.
  로봇이 아는 CAD 루트 반지름으로 이만큼 되돌린다. 관은 둘레를 따라 이어지므로 이음매 양 끝에서도 패치를 자르지 않는다
  (판은 끝에서 자름). 그래서 열변형·틈새는 이음매 밖에서 끝 값을 쓴다(아니면 시작 구간 스캔에서 진행각이 0.35° 치우쳤다).
- 노이즈 없는 단면 측정이 정답과 같은지 네 군을 같은 방법(혼합 40개 × 용접 중 12점 + 시작 구간 스캔 7점)으로 봤다. 파이프 최대 차이
  좌우 0.035, 높이 0.036 mm, 작업각 0.015°, 진행각 0.025°로 다른 군(0.03–0.05 mm, 진행각 0.08–0.14°)과 같은 수준이고 평균 치우침은 0이다(`test/test_pipe.py`).
- Isaac 장면은 관 둘레 전체 메시를 만든다(용접 구간 밖은 오차를 양 끝 값으로). `expert_to_sim.py` 자동 배치는 호의 가운데(꼭대기)를 토치 아래에 둔다.
  Isaac 물리 실행(추종, IK 도달 범위)은 T 필릿만 확인했고 코너·V홈·파이프는 아직이다. 확인 순서는 아래 "Isaac 물리 검증 (코너·V홈·파이프)".

### Isaac 물리 검증 (코너·V홈·파이프)

운동학 에피소드는 완벽 추종이라 opti3 도달 범위와 Isaac 관절 추종을 보지 않는다. 시편군마다 1/5 묶음(약 67개)으로 본다.

1. 시나리오: `for %f in (fillet_corner butt_v pipe_girth) do python -m sim_errors.make_scenarios --batch --scale 0.2 --family %f --out exp_isaac\batch`
2. 도달 점검: `python sim_bridge\run_batch.py exp_isaac\batch --out exp_isaac\reach --reach-only --follower-urdf ...\opti3.urdf`
3. 화면 확인 (receiver를 `--headless` 없이): 군마다 `--only pipe_clean --limit 1`처럼 하나씩 돌려, 모재가 토치 아래에 놓이고
   토치 끝이 빨간 선을 따라가는지 본다. 파이프는 토치가 호를 따라 ±50° 기운다.
4. 일괄 (`--headless --lockstep`): `python sim_bridge\run_batch.py exp_isaac\batch --only pipe_ --out exp_isaac\episodes\pipe --follower-urdf ...`
   (`corner_`, `butt_`도 같게). 군마다 `batch_report.json`.

판정 기준은 T 필릿 Isaac 실행(66개 모두 통과, 추종 95% 약 0.55 mm)과 같다: 모두 통과, 추종 95% 2 mm 미만, IK 경고 비율, 용접 시간.

## 단면 센서 모델 (평면 맞춤)

토치 앞 30 mm에서 카메라가 보는 작은 패치(이음매 방향 10 mm, 판마다 뿌리에서 15 mm, 1 mm 간격)의 두 판 면 위 점을 실제 변형된 모재에서 뽑고, 점마다 노이즈(σ 0.2 mm)와 측정 구멍(10%)을 넣은 뒤 판마다 평면을 맞춘다. 두 평면의 교선이 뿌리선이고, 그 위치가 좌우·높이, 두 평면이 만드는 이음매 좌표계(x = 교선, z = 법선 이등분)의 회전이 작업각·진행각 측정이다. 틈새 폭은 정답 + 노이즈(σ 0.1 mm). 패치 전체 실패는 5%. 설정은 `config/part_errors.yaml`의 `sensors`.

작업각(이음매 축 둘레 회전)은 뿌리 위치를 바꾸지 않으므로 이 각도 측정 없이는 정책이 배울 수 없다. 기본 설정에서 측정 노이즈는 좌우·높이 약 0.04 mm, 작업각 약 0.15°, 진행각 약 0.3°.

**용접 전 시작 구간 스캔 (`prescan_mm`, 기본 30):** 단면은 토치 앞 30 mm에서만 재므로 이음매 시작 30 mm는 용접 중에 한 번도 보이지 않는다. 첫 가접(s 0.02~0.08)이 이 구간에 있어 남은 높이 오차의 대부분이 여기서 나왔다(learning/README.md "남은 높이 오차의 원인"). 그래서 아크를 켜기 전에 손목 카메라로 시작 구간을 한 번 훑는다고 보고, `PartErrorModel.prescan()`이 s_arc = 0 상태의 단면을 0.5 mm 간격으로 같은 평면 맞춤 모델(노이즈·측정 실패 포함)로 잰다. 스캔은 시나리오만으로 정해지므로 에피소드 기록에는 없고, 변환(`learning.to_lerobot`)과 평가가 시나리오에서 다시 계산해 버퍼를 먼저 채운다. 이전 시나리오(설정에 `prescan`이 없음)는 스캔이 없고, `resense`로 지금 설정을 넣으면 생긴다.

센서 모델을 바꿨을 때 이미 만든 에피소드는 Isaac을 다시 돌리지 않고 단면 열만 다시 계산한다(단면 값은 시나리오와 진행도만으로 정해짐).

```bat
python -m sim_errors.resense episodes\t_small --out episodes\t_small_prof
python sim_bridge\run_batch.py batches\t_small --out episodes\t_small_prof --report-only
```

## 오차별 단독 검증

여러 오차가 섞인 에피소드로는 하나가 틀려도 묻히므로, 오차를 하나만 크게 과장해서 켠 시나리오로 따로 확인한다.

1. `python -m sim_errors.make_scenarios --single all --out scenarios_single` → 13개(코너 필릿은 `--family fillet_corner`로, 맞대기 V홈은 `--family butt_v`로 14개, 파이프 원주는 `--family pipe_girth`로 15개) `single_<오차>.json`과 기대 정답 표(진행도 0, 0.25, 0.5, 0.75, 1에서 좌우·높이·작업각·진행각·틈새·가접)를 출력
2. 오차마다 receiver(`--scenario scenarios_single\single_<오차>.json --kp 1e5 --kd 2e3`)와 `expert_to_sim.py`를 실행
3. `check_episode`로 8항목을 확인하고, 그래프가 1의 기대 정답 표와 같은 모양인지, Isaac 화면이 계획 문서 "오차별 단독 검증" 표의 화면 기대와 같은지 본다

코너 필릿 14종은 운동학 실행(`run_batch.py --kinematic`)으로 모두 점검을 통과했다. 맞대기 V홈은 노이즈 없는 단면 측정이
정답과 0.01 mm·0.01° 안에서 같고(단차만 위 치우침), 혼합·가혹 운동학 에피소드가 8항목을 모두 통과했다(`test/test_butt.py`). 바닥 판 평평도·웹 직진도의 단면 센서 "주의"는 T 필릿과 같다(과장한 5 mm 휨에서 30 mm 앞 측정이 토치 위치와 달라서).

단독 시나리오는 단면 센서(`laser`)의 노이즈와 측정 실패도 0이라 측정 점이 정답 선 위에 정확히 겹친다(토치 앞 30 mm에서 잰 값이라 그만큼 앞에 찍힘).

## 기록 점검 (check_episode.py)

| 항목 | 통과 조건 | 실패하면 |
| --- | --- | --- |
| 단계 순서 | approach → descend → weld → retract → 완료 (용접 구간만 담은 에피소드는 weld → 완료) | 중단됐거나 IK 실패로 멈춤 |
| IK 상태 | 모든 주기 `ok` (95% 넘으면 주의) | `approx`·`ik_failed`가 많으면 모재가 도달 범위 경계에 있음 |
| 진행도 | s가 줄지 않고 1까지 | 에피소드가 끝나지 않음 |
| 정답 재계산 | 기록된 정답 = 시나리오로 다시 계산한 값 | 시나리오 파일과 기록이 어긋남 (코드 버전 차이) |
| 목표 기하 | 전문가 목표 = 실제 이음매 + standoff(+가접) + 위빙, 토치 방향 = 이음매 쪽 + 미는 각, 보낸 목표 = 전문가 목표 + 기록된 어긋남 | 규칙 전문가 버그 |
| 추종 오차 | 용접 중 토치 팁(실측 관절의 URDF FK)과 목표 차이 95%가 2 mm 미만 (6 mm 미만은 주의) | Isaac 관절이 명령을 못 따라감: 게인, 속도 제한 확인 |
| 단면 센서 (`laser`) | 측정 실패율이 설정과 비슷, 좌우·높이·틈새 폭의 정답 대비 편차가 노이즈 수준 | 센서 모델 문제 |
| 용접 시간 | 길이 / 속도 범위 안 | 진행 속도 규칙 문제 |

추종 오차는 URDF FK로 계산하므로, Isaac 장면의 토치 팁이 URDF와 다르면 여기서는 드러나지 않는다. 그건 Isaac 화면에서 토치 끝이 빨간 선 위를 지나가는지로 확인한다.

## 모델 요약

- 모재: T이음 필릿, ㄱ자 코너 필릿, 맞대기 V홈, 파이프 원주 (위 "시편군"). 필릿 모재 좌표계 원점 = 이음매 시작점, x = 이음매 방향, 바닥 판 윗면 z = 0, 웹 판 용접 쪽 면 y = 0. 맞대기와 파이프는 위 "시편군" 참고.
- 추정 경로 = 명목 경로 × (배치 자세 × ICP 잔차). 용접 전에 정해지고 고정.
- 실제 경로 = 배치 자세 × (명목 + 형상 오차 + 열변형 + 밀림). 열변형과 밀림은 시간이 아니라 아크 진행도 s_arc의 함수.
- 정답 e = 추정 경로 좌표계에서 본 (실제 − 추정). y = 좌우, z = 높이. 각도 정답 = 두 좌표계의 회전 차이(x = 작업각, y = 진행각).
- 틈새는 이음매 위치를 바꾸지 않고, 규칙 전문가의 위빙 진폭·진행 속도에만 영향을 준다(`expert` 설정, WPS 값으로 바꿀 것).
- 다음 패스: 이번 패스의 잔류 각변형·휨을 다음 패스의 용접 전 형상으로 넘긴다. 틈새와 가접은 0.

## 아직 없는 것

에피소드 생성 사양(Claude Doc "에피소드 생성 사양")과 지금 코드의 차이다. 구현 순서는 그 문서에 있다.

실제로 용접할 이음 형태는 아직 정해지지 않았다. 그래서 T 필릿 하나로 일괄 생성부터 학습·평가까지 먼저 한 바퀴 돌려 파이프라인을 확인하고(학습용 묶음 일괄 생성, [learning/README.md](../learning/README.md)), 그다음 사양 순서대로 코너 필릿, 맞대기 V홈, 파이프 원주를 모두 더했다.

직선/위빙 모드는 정해져 구현했다: 작업 시작 때 WPS의 일부로 정하고 에피소드 안에서는 바꾸지 않음, 묶음마다 반반, 사인파 위빙, 직선 모드는 위빙 진폭 0이고 틈새가 커지면 속도만 줄임. 모드는 정책 조건 입력(원-핫)이다.

- 고정 배치: 지금은 홈 자세(`--home-q`)의 토치 팁 근처 고정 자리다. 도달 범위 지도로 여유가 가장 큰 자리를 고르는 일은 아직.
- 작업대·지그 메시와 충돌 검사: 모재는 표시 전용이다.
- 규칙 상태기계 검사용 전체 주기(대기~후퇴) 에피소드를 묶음에 섞기: `--batch`는 용접 구간만 만든다. 전체 주기는 `episode` 없는 시나리오(`--n`)로 만든다.
- 시편군 확장: T 필릿, ㄱ자 코너 필릿, 맞대기 V홈, 파이프 원주(둘 다 루트 패스)가 있다. 코너·V홈·파이프의 Isaac 물리 실행 확인, 파이프의 다른 자세(관 아래쪽 5G 전체, 세운 관 2G), 시편군 안에서 치수를 범위로 뽑는 것(사양 "치수 범위"), 코너의 선택 V홈, 맞대기 다층 패스, 실제 depth 카메라로 판 윗면 단차를 재는 정확도 확인은 아직.
- 단독 묶음의 오차 서명 자동 비교 (지금은 `--single` 검증에서 눈으로 본다)
- 렌더링한 depth 점군으로 실제 ICP 돌리기 (지금은 ICP 잔차를 분포에서 뽑음)
- 다층 용접의 비드 형상
- 카메라 이미지 기록 (기록 전용, 정책 입력 아님)
- 정책을 Isaac에서 모는 실행기 (추종 오차가 들어간 닫힌 루프 평가). DAgger는 보류 (learning/README.md "다음 단계")
