# 보정 정책 학습 (learning)

시뮬 규칙 전문가 에피소드 묶음으로 기준 보정 정책(작은 MLP 또는 GRU 행동 복제)을 학습하고, 보정 0 기준선 대비 정답 오차로 평가한다. 설계 근거는 [아키텍처](../README.md), Claude Doc "에피소드 생성 사양"의 "기록 형식"과 "구현 순서".

| 파일 | 하는 일 |
| --- | --- |
| `features.py` | 관측·행동 정의, 단면 거리 버퍼. 변환과 평가가 같은 코드를 쓴다 |
| `to_lerobot.py` | 에피소드 .npz(100 Hz) → `frames.npz`(10 Hz, 학습용)와 LeRobotDataset |
| `train_bc.py` | MLP/GRU 행동 복제, 입력 묶음 선택, `policy.pt` 저장 |
| `evaluate.py` | 열린 루프(기록 관측으로 예측) + 닫힌 루프(운동학, 정책이 직접 토치를 몸) 평가. 정책 자리에 `rule`/`rule-noprescan`을 주면 학습 없는 규칙 기준선 |
| `report_evals.py` | 여러 `eval.json`을 표 하나로 (실험 워크플로 요약) |

## 관측과 행동

관측 61개 (단위 mm, deg). 기본 입력은 `section,profile,progress,mode` (토치 자세는 뺌).

| 묶음 (`--obs`) | 개수 | 내용 |
| --- | --- | --- |
| `section` | 36 | 단면 거리 버퍼: 토치 뒤 10 mm ~ 앞 30 mm, 5 mm 간격 9점 × (좌우, 높이, 틈새 폭) + 9점 유효 표시. 단면은 토치 앞 30 mm에서만 재므로 잰 값을 이음매 위치와 함께 쌓아 꺼낸다. 값은 추정 경로 기준 편차(토치 기준 측정 + 그때 토치 자세) |
| `profile` | 18 | 같은 버퍼 9점 × (작업각, 진행각): 단면 패치의 두 판 면 평면 맞춤으로 구한 이음매 좌표계 회전 ([sim_errors/README.md](../sim_errors/README.md) "단면 센서 모델") |
| `torch` | 4 | 추정 경로 기준 토치 자세 어긋남 (좌우, 높이, 작업각, 진행각). 위빙·섭동·시작 어긋남 포함. 직전 정답을 따라 하는 지름길이 생겨 기본 입력에서 뺌 |
| `progress` | 1 | 진행도 s |
| `mode` | 2 | 위빙/직선 원핫 |

행동 7개 (정답 = 규칙 전문가): 좌우, 높이(CTWD, 가접 올림 포함) [mm], 작업각, 진행각 [deg], 진행 속도 [mm/s], 위빙 진폭 [mm], 위빙 주파수 [Hz].

## 실행 순서

저장소 루트에서. 학습·변환은 `pip install torch "lerobot[dataset]"` (lerobot은 Python 3.12 이상, conda `weld` 환경에서 됨). lerobot이 없으면 `frames.npz`만 만든다.

```bat
python -m sim_errors.make_scenarios --batch --scale 0.2 --out batches\t_small
python sim_bridge\run_batch.py batches\t_small --out episodes\t_small --follower-urdf C:\...\opti3.urdf
python -m learning.to_lerobot episodes\t_small --out datasets\t_small
python -m learning.train_bc datasets\t_small --model mlp --out runs\mlp
python -m learning.train_bc datasets\t_small --model mlp --obs section,progress,mode --out runs\mlp_noprofile
python -m learning.train_bc datasets\t_small --model gru --out runs\gru
python -m learning.evaluate runs\mlp\policy.pt runs\mlp_noprofile\policy.pt runs\gru\policy.pt --data datasets\t_small --episodes episodes\t_small
```

Isaac 없이 전체 흐름만 볼 때는 두 번째 줄을 `--kinematic --jobs 4`(완벽 추종 가정)로 바꾼다.

비교용 명령: 시작 구간 스캔 없이 변환(`--no-prescan`), 학습 없는 규칙 기준선(`rule`, `rule-noprescan`), eval.json 여러 개를 표 하나로(`report_evals`).

```bat
python -m learning.to_lerobot episodes\t_small --out datasets\t_small_noscan --no-prescan
python -m learning.evaluate rule rule-noprescan --data datasets\t_small --episodes episodes\t_small --rule-dir runs
python -m learning.report_evals runs\mlp\eval.json runs\rule\eval.json runs\rule-noprescan\eval.json
```

사양 수량(330개) 생성부터 평가까지는 GitHub Actions의 "Experiment" 워크플로(`.github/workflows/experiment.yml`)를 Run workflow로 돌린다. 약 30분, 러너 약 3시간분이라 push로는 돌지 않는다. 결과는 실행 요약의 표와 `eval-*` 아티팩트.

- 나눔은 시나리오의 `episode.split`(에피소드 단위 학습 80 · 검증 10 · 시험 10, 가혹은 모두 시험).
- 평가 결과는 `<정책 폴더>/eval.json`(규칙 기준선은 `<rule-dir>/rule/eval.json`), 학습 곡선은 `train_log.json`.
- 높이 오차는 시작 30 mm와 나머지로도 나눠 나온다. 시작 구간 스캔으로 학습한 정책(`policy.pt`의 `prescan`)은 닫힌 루프에서도 스캔을 넣는다.
- 닫힌 루프 평가는 로봇이 명령을 바로 따라간다고 가정한다. Isaac 추종 오차는 들어가지 않는다.

## 첫 한 바퀴 결과 (운동학 데이터, 2026-11-17)

Isaac 대신 운동학 에피소드 66개(1/5 수량: 깨끗함 6, 단독 13, 혼합 41, 가혹 6)로 흐름 전체를 돌렸다. 학습 48, 검증 6, 시험 12(가혹 6 포함). 학습은 CPU로 정책 하나에 10초 안쪽.

닫힌 루프 RMS, 시험 12개 전체 (정책 / 보정 0, 개선율)

| 정책 | 좌우 mm | 높이 mm | 작업각 deg | 진행각 deg |
| --- | --- | --- | --- | --- |
| MLP, 전체 입력 | 0.24 / 1.30 (82%) | 0.49 / 1.31 (62%) | 0.27 / 0.23 (−17%) | 0.67 / 0.68 (2%) |
| MLP, 토치 자세 뺌 | 0.21 / 1.30 (83%) | 0.41 / 1.31 (69%) | 0.26 / 0.23 (−15%) | 0.66 / 0.68 (3%) |
| GRU, 전체 입력 | 0.24 / 1.30 (82%) | 0.64 / 1.31 (51%) | 0.33 / 0.23 (−42%) | 0.73 / 0.68 (−7%) |
| GRU, 토치 자세 뺌 | 0.30 / 1.30 (77%) | 0.48 / 1.31 (63%) | 0.25 / 0.23 (−9%) | 0.68 / 0.68 (1%) |

이 결과로 본 것 (데이터가 작아 방향만 본다)

- 좌우·높이는 배운다. 보정 0 대비 좌우 오차 약 80%, 높이 60–70% 줄었다.
- 각도는 못 배운다. 단면 버퍼에는 좌우·높이·틈새만 있어 작업각·진행각을 알 단서가 거의 없다. 정답 각도도 0.1–0.9°로 작다. 단면 프로파일(두 판 면의 기울기)을 입력에 넣거나, 각도를 행동에서 빼고 규칙(이음매 좌표계 그대로)으로 두는 것 중 하나를 골라야 한다.
- 토치 자세 입력은 지름길을 만든다. 열린 루프에서는 토치 자세가 있는 쪽이 더 좋지만(직전 정답이 토치 자세에 그대로 들어 있어서), 닫힌 루프 높이 오차는 오히려 나빠진다. 기준 정책은 토치 자세를 빼고(또는 위빙 위상만 남기고) 시작하는 쪽을 추천한다.
- GRU가 MLP보다 낫지 않다. 지금 크기에서는 MLP로 시작한다.
- 수량: 학습 손실이 검증 손실보다 훨씬 낮아(과적합) 1/5 수량은 부족하다. 사양대로 군당 300개로 늘린 뒤 다시 비교한다.

## 단면 프로파일 추가 후 (운동학 데이터, 2026-11-18)

같은 66개 기록의 단면 열을 평면 맞춤 모델로 다시 계산하고(`sim_errors.resense`) 같은 나눔으로 비교했다. 닫힌 루프 RMS, 시험 12개 전체 (정책 / 보정 0, 개선율)

| 정책 | 좌우 mm | 높이 mm | 작업각 deg | 진행각 deg |
| --- | --- | --- | --- | --- |
| MLP, 프로파일 없음 | 0.22 / 1.30 (83%) | 0.41 / 1.31 (69%) | 0.27 / 0.23 (−16%) | 0.66 / 0.68 (3%) |
| **MLP, 프로파일 (기본)** | 0.23 / 1.30 (82%) | 0.42 / 1.31 (68%) | 0.07 / 0.23 (70%) | 0.25 / 0.68 (64%) |
| GRU, 프로파일 | 0.29 / 1.30 (78%) | 0.47 / 1.31 (64%) | 0.06 / 0.23 (74%) | 0.29 / 0.68 (57%) |
| MLP, 프로파일 + 토치 자세 | 0.24 / 1.30 (82%) | 0.56 / 1.31 (57%) | 0.07 / 0.23 (68%) | 0.23 / 0.68 (66%) |

- 판 면 기울기를 넣자 각도를 배운다. 좌우·높이는 그대로다.
- 토치 자세를 넣으면 이번에도 닫힌 루프 높이가 나빠진다(68% → 57%).
- GRU는 여전히 MLP보다 낫지 않다.

## Isaac 기록으로 같은 비교 (2026-11-18)

사용자 PC의 Isaac 66개 기록을 resense로 다시 계산해 같은 나눔으로 비교했다. 닫힌 루프 개선율(시험 12개)이 운동학 결과와 1~5%p 안에서 같다. MLP+프로파일: 좌우 81%, 높이 66%, 작업각 65%, 진행각 63%. 프로파일 없음: 83%, 68%, −16%, 1%. GRU+프로파일: 78%, 64%, 76%, 56%. 추종 오차(95% 0.55 mm)는 결론을 바꾸지 않는다. 단면 측정이 시나리오와 진행도만으로 정해지기 때문이다.

## 수량·섭동 비교 (운동학 330개, 2026-11-18)

사양 수량(`--scale 1.0`, 깨끗함 30 · 단독 65 · 혼합 205(절반 섭동) · 가혹 30)을 운동학으로 만들고(`--kinematic --jobs 4`, 33분), 학습 에피소드 수와 섭동 유무만 바꿔 같은 검증 29개 · 시험 59개(가혹 30 포함)로 비교했다. 입력은 모두 기본(section, profile, progress, mode).

```bat
python -m learning.train_bc datasets\t_full --max-train 48 --out runs\mlp_n048
python -m learning.train_bc datasets\t_full --no-perturb --out runs\mlp_noperturb
python -m learning.evaluate runs\mlp_n048\policy.pt runs\mlp_noperturb\policy.pt --data datasets\t_full --episodes episodes\t_full --jobs 4
```

닫힌 루프 개선율, 시험 59개 (위빙 차 = 전문가 규칙과의 위빙 진폭 RMS 차, mm)

| 정책 | 학습 에피소드 | 최저 검증 손실 (epoch) | 좌우 | 높이 | 작업각 | 진행각 | 위빙 차 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| MLP | 48 | 0.074 (1) | 83% | 69% | 62% | 66% | 0.22 |
| MLP | 120 | 0.052 (2) | 84% | 72% | 62% | 70% | 0.17 |
| MLP | 242 (전체) | 0.053 (1) | 85% | 71% | 66% | 71% | 0.12 |
| MLP, 섭동 포함 | 156 | 0.053 (2) | 84% | 72% | 64% | 71% | 0.17 |
| MLP, 섭동 뺌 | 156 | 0.066 (1) | 85% | 70% | 65% | 70% | 0.17 |
| GRU | 242 (전체) | 0.035 (13) | 82% | 70% | 80% | 70% | 0.13 |

- **수량:** 학습 에피소드를 5배로 늘려도 좌우·높이는 1~3%p만 좋아진다. 검증 손실은 120개에서 멈추고, MLP는 어느 수량에서나 1~2 epoch 뒤부터 과적합한다. 남은 오차는 데이터가 모자라서가 아니었다. 대부분은 단면이 한 번도 보지 못한 이음매 시작 30 mm에서 나왔다(아래 "남은 높이 오차의 원인"). 위빙 진폭은 수량에 따라 꾸준히 좋아진다.
- **섭동:** 같은 156개에서 섭동이 있든 없든 결과가 같다. 토치 자세를 입력에서 뺀 뒤로는 섭동이 정책 관측을 바꾸지 않기 때문이다. 단면 값은 추정 경로 기준이라 토치가 어디 있든 같고, 정책 출력은 진행 속도를 통해 진행도에만 영향을 준다. 같은 이유로 열린 루프와 닫힌 루프 오차가 거의 같다(MLP 전체: 좌우 0.212 대 0.21 mm). 섭동 뺌의 검증 손실이 높은 것은 혼합 에피소드 비율이 줄어서다.
- **GRU:** 데이터가 많으면 과적합하지 않고(13 epoch에서 최저) 검증 손실이 가장 낮다. 작업각은 MLP보다 확실히 낫고(80% 대 66%) 나머지는 비슷하다.

## 남은 높이 오차의 원인: 시작 30 mm 사각지대 (2026-11-18)

남은 높이 오차(약 0.4 mm)는 센서 노이즈가 아니라 이음매 시작 30 mm에서 나왔다. 단면은 토치 앞 30 mm에서만 재고 에피소드는 토치를 시작점에 놓고 시작하므로, 시작 30 mm는 용접 내내 한 번도 측정되지 않는다. 첫 가접(s 0.02~0.08)이 이 구간에 있다.

학습 없는 규칙(버퍼의 토치 위치 값을 그대로 씀, `evaluate rule`)을 사양 묶음 시험 59개에서 닫힌 루프로 돌려 나눠 봤다 (높이 RMS, 보정 0 = 1.34 mm).

| 조건 | 높이 mm |
| --- | --- |
| 노이즈 있음, 10 Hz | 0.56 |
| 노이즈 없음, 또는 100 Hz | 0.56 (변화 없음, 노이즈는 각도에만 영향) |
| 토치 위치에서 바로 잰다고 가정 | 0.01 |
| 비어 있으면 가장 가까운 유효 점 (`rule-noprescan`) | 0.50 (시작 30 mm 1.48, 나머지 0.21, 제곱오차의 84%가 시작 구간) |
| + 용접 전 시작 구간 스캔 (`rule`) | 0.21 |

단독 오차로 보면 가접·ICP·형상 오차는 시작 구간에서만 남고, 나머지 구간의 0.21 mm는 잰 뒤 모재가 움직이는 오차다(갑자기 튐 0.26, 서서히 밀림 0.18, 세로 휨 0.05 mm).

그래서 아크를 켜기 전에 시작 30 mm를 손목 카메라로 한 번 훑는 단계를 넣었다(사용자 결정, `sensors.prescan_mm`, [sim_errors/README.md](../sim_errors/README.md) "단면 센서 모델"). 변환(`to_lerobot`)과 닫힌 루프 평가가 시나리오에서 스캔을 계산해 버퍼를 먼저 채운다. `--no-prescan`으로 끈 데이터와 비교했다.

### 스캔 있음·없음 재학습 (운동학 330개, GitHub 실험 워크플로)

`.github/workflows/experiment.yml`(사양 묶음 생성 6조각 → 변환 → 학습 → 정책별 평가, 약 30분)로 돌렸다. 학습 242 · 검증 29 · 시험 59(가혹 30 포함), 입력은 기본(section, profile, progress, mode). 닫힌 루프 RMS (보정 0 대비 개선율), 시험 59개.

| 정책 | 스캔 | 좌우 mm | 높이 mm | 작업각 deg | 진행각 deg | 높이 시작 30 mm | 높이 나머지 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **MLP** | O | 0.18 (84%) | **0.20 (85%)** | 0.06 (74%) | 0.15 (76%) | 0.22 | 0.20 |
| MLP | X | 0.20 (82%) | 0.41 (69%) | 0.06 (71%) | 0.21 (65%) | 1.14 | 0.23 |
| GRU | O | 0.21 (81%) | 0.23 (83%) | 0.04 (84%) | 0.13 (78%) | 0.25 | 0.23 |
| GRU | X | 0.24 (79%) | 0.42 (68%) | 0.04 (82%) | 0.20 (67%) | 1.11 | 0.27 |
| 규칙 | O | 0.19 (83%) | 0.21 (85%) | 0.16 (28%) | 0.30 (49%) | 0.15 | 0.21 |
| 규칙 | X | 0.20 (83%) | 0.50 (63%) | 0.16 (28%) | 0.34 (43%) | 1.48 | 0.21 |

보정 0: 좌우 1.14, 높이 1.34, 작업각 0.22, 진행각 0.60. 가혹 묶음만 보면 MLP 스캔 높이 0.24 mm(86%), 스캔 없음 0.51 mm(69%).

- 스캔을 넣으면 MLP 높이 오차가 절반이 된다(0.41 → 0.20 mm). 시작 구간이 1.14 → 0.22 mm로 줄고, 진행각도 65% → 76%로 좋아진다(시작 구간 각도도 보이게 되어서).
- MLP 높이(0.20 mm)가 규칙(0.21 mm)과 같다. 정책이 지금 센서로 알 수 있는 만큼은 다 배웠다는 뜻이다. 남은 0.2 mm는 잰 뒤 모재가 움직이는 오차(밀림, 튐, 휨)라 단면 30 mm 앞 측정으로는 줄지 않는다.
- 각도는 정책이 규칙보다 훨씬 낫다(작업각 74% 대 28%). 버퍼 9점의 판 면 기울기를 모아 노이즈를 거르기 때문으로 보인다.
- GRU는 작업각이 조금 낫고(84% 대 74%) 높이·좌우는 MLP가 조금 낫다. 기준 정책은 계속 MLP로 둔다.
