# 용접 로봇 설계 결정

## 한눈에 보기

아키텍처를 바꿀 때 참고하도록, 주제마다 채택한 안, 검토한 대안, 이유, 바꾸면 영향받는 곳을 모았습니다. 현재 설계 자체는 [용접 로봇 아키텍처](../README.md)에 있습니다.

| 주제 | 채택한 안 | 검토한 대안 |
| --- | --- | --- |
| 작업 시작 | 명시적 시작 트리거, 클러치와 분리 | 클러치 겸용, 검출 모듈이 자동 시작 |
| 단계 전이 판단 | 규칙 상태기계 | Jev가 처음부터 모든 전이 결정, 규칙으로 시작한 뒤 Jev와 비교 |
| 전이 자율 수준 | 트리거 이후 모든 전이 자동 | 아크 ON은 사람 승인 |
| 아크 ON/OFF와 크레이터 | 단계 전이 + 용접기 설정 | 정책 행동에 포함 |
| 계층 구조 | 경로는 계산, 정책은 보정만 학습 | 정책이 경로까지 학습 |
| 이음매 경로 계산 | 모재 CAD + depth 카메라 정합 | 텔레옵 교시, 터치 센싱, 레이저 추적, 아크 센싱 |
| 용접 중 이음매 관측 | 손목 depth 카메라 단면 (아크 없는 시연 환경 기준) | 레이저 라인, 아크 센싱, 필터 카메라, RGB 이음매 검출, RGB 영상 직접 입력 |
| 이음매 시작 구간 사각지대 | 용접 전 시작 구간 스캔 (아크 끄고 30 mm) | 시작점 뒤에서 출발(리드인), 그대로 둠 |
| 정책 조건 입력 | 직선·위빙 모드 + 진행도 s, WPS는 고정값 | 전체 단계 ID, WPS 조건 입력 |
| 정책 모델 | MLP/GRU 행동 복제 (시뮬 전문가 DAgger는 보류) | ACT, Diffusion Policy, 사전학습 VLA |
| 보정 정책 학습 데이터 | 시뮬 규칙 전문가 데이터만으로 학습 (실기 시연 미세조정은 보류) | 실기 시연 미세조정 추가, 실기 시연만, 시뮬 텔레옵 시연, 개입 데이터로 미세조정 |
| 사람 개입 | 공유 제어 (모델 보정에 사람 보정을 더함) | 넘겨받기 (개입 중 정책 정지) |
| 개입 데이터 활용 | 작은 잔차 모델 학습 (정답에 유지 오프셋 포함) | 같은 모델 재학습, 둘 다 비교, 클러치 ON 동안의 델타만 정답 |
| 축별 권한과 놓은 뒤 처리 | 높이·좌우·각도는 사람, 진행·위빙은 모델, 오프셋 유지 + 초기화 버튼 | 다른 배분, 서서히 감쇠 |
| 제어 주체 중재 | 클러치 + 축별 권한 규칙 | Jev가 중재 |
| 텔레옵 방식 | TCP(토치 끝) | 관절 방식 |
| 실제 로봇 장치 | 미정 | 클러치·트리거: 풋페달, 손잡이 버튼, PLC 신호. 실기 검증 팔로워 암: LeBot 검토 중 |

## 작업 흐름

### 작업 시작: 명시적 시작 트리거

- **채택:** 사람이 시작 트리거를 눌러야만 작업이 시작됩니다. 클러치는 사람 보정을 켜고 끄는 역할만 합니다.
- **대안:** 클러치를 시작 신호로 겸용하기. 트리거 없이 검출 모듈이 시작 시점을 정하기.
- **이유:** 클러치를 겸용하면 용접공이 토치 위치만 잡고 클러치를 떼는 순간 작업이 시작됩니다. 자동 시작은 아크의 빛, 흄, 화상 위험 때문에 현장에서도 대부분 사람이 확인합니다.
- **바꿀 때:** 자동 시작으로 가려면 상위 층에 미용접 이음매 검출(비드 유무 구분)과 시작 조건 확인(모재 고정, 셀 안에 사람 없음)이 더 필요합니다. 중간안은 검출 모듈이 "준비됨"을 알리고 작업자가 한 번 누르는 방식입니다.

### 단계 전이 판단: 규칙 상태기계

- **채택:** 대기 → 접근 → 아크 ON → 용접 → 크레이터 → 후퇴 사이의 전이를 코드의 규칙 상태기계가 정합니다. 조건은 시작 트리거, 시작점 도달, 점화 확인, 진행도 s = 1(경로 끝), 크레이터 시간 종료이고, 용접 중 추종 오차 초과·이음매 분실·IK 실패가 이어지면 아크를 끄고 일시정지합니다.
- **대안:** 처음부터 Jev가 모든 전이를 고르기. 규칙으로 시작하고 Jev는 같은 입력으로 shadow mode에서 비교한 뒤 이기면 교체.
- **이유:** 학습하는 단계가 용접 하나뿐이고, 전이 입력(시작점 도달, 점화 확인, 진행도, 추종 오차)은 사람이 보고 바로 고를 수 있는 수준이라 규칙으로 충분합니다. 규칙은 결정론적이라 시뮬에서 검증하기 쉽고, 외부 API 접근 권한, 네트워크 지연과 단절 대비, 용접에서의 확률 보정 검증 같은 Jev의 선행 조건이 없어집니다.
- **위험:** 전이 임계값(위치·자세 오차, 추종 오차, 이음매 분실 시간)은 Isaac Sim 로그로 정하고 실기에서 다시 맞춰야 합니다. 전류 파형이나 용융지 이상처럼 사람이 한눈에 판단하기 어려운 신호가 늘면 규칙이 복잡해집니다.
- **바꿀 때:** Jev를 다시 넣으려면 상태를 수치와 플래그로 요약하고(`tracking_error_high`처럼 임계값은 코드가 계산), 현재 단계에서 허용된 전이만 선택지로 넣으며, 선택지별 결과(도달 가능 여부, 남은 거리)는 코드가 계산해 넘깁니다(arXiv 2610.01834). 응답 전이나 단절 때는 현재 단계를 유지하고, 신뢰도가 낮으면 현재 단계 유지나 일시정지를 택합니다. Isaac Sim 로그로 정확도를 확인한 뒤 shadow mode에서 규칙과 비교합니다. 자세한 설계는 [Jev 의사결정 모델 설계 고려사항](https://claude.ai/artifact/StWcQDXxRGm56MEgxkNRmt)에 있습니다.

### 전이 자율 수준: 트리거 이후 모두 자동

- **채택:** 시작 트리거 이후 아크 ON을 포함한 모든 전이를 사람 승인 없이 실행합니다. 사람은 클러치와 하드 인터록으로 개입합니다.
- **대안:** 아크 ON처럼 되돌릴 수 없는 전이는 상태기계가 제안만 하고 사람이 버튼으로 확정. 일시정지·핸드오버 같은 안전 쪽 전이만 즉시 실행.
- **이유:** 시작은 사람이 확인하고, 그 뒤 안전은 클러치와 하드 인터록이 보장합니다. 점화 실패나 추종 오차 초과처럼 조건이 어긋나면 사람에게 넘기는 대신 일시정지나 후퇴 같은 안전 쪽 전이를 택합니다.
- **바꿀 때:** 승인 방식으로 가려면 승인 버튼 입력과 "승인 대기" 상태를 추가하고, 조건이 어긋날 때의 처리를 "사람에게 넘김"으로 바꾸면 됩니다.

### 아크 ON/OFF와 크레이터: 단계 전이 + 용접기 설정

- **채택:** 상태기계가 아크 ON 또는 크레이터 단계로 넘기면 코드가 용접기에 명령을 보내고, 점화 순서와 크레이터 전류·시간은 용접기 설정값을 씁니다. 시뮬과 시연 환경에는 실제 용접기가 없어, 점화 확인과 아크 OFF 확인은 타이머로 만든 가상 신호로 대신합니다.
- **대안:** 정책이 아크 ON/OFF와 크레이터 처리를 행동으로 출력.
- **이유:** 되돌릴 수 없는 아크 명령을 결정론적으로 두고, 학습 범위를 용접 단계 하나로 유지합니다. 대안은 점화 뒤 용융지가 생길 때까지 머무는 타이밍이나 끝점 비드를 보고 크레이터 시간을 조절하는 숙련 동작을 배울 수 있지만, 점화 타이밍 오류와 경계에서의 ON/OFF 떨림 위험이 생깁니다.
- **바꿀 때:** 정책 행동에 아크 명령을 넣고, 학습 단계를 아크 ON·용접·크레이터 셋으로 늘리며, 조건 입력에 단계 ID를 추가합니다. 시연에는 용접공의 아크 명령을 정답으로 기록해야 하고, 출력에 최소 유지 시간이나 히스테리시스를 두며, 크레이터 전류·시간은 용접기 설정 범위 안으로 제한합니다. 하드 인터록은 그 세 단계 밖의 점화를 막아야 합니다.

## 경로와 정책

### 계층 구조: 경로는 계산하고 보정만 학습

- **채택:** 상위 층은 이음매 경로를 고전 방식으로 계산하고, 하위 층 정책은 그 경로 기준의 보정값만 학습합니다.
- **대안:** 정책이 카메라 입력만으로 토치 경로까지 학습(끝에서 끝까지).
- **이유:** 위치 정확도는 CAD와 센서가 책임지고, 정책은 경로 대비 보정만 배우므로 데이터가 적게 듭니다. 출력이 수 mm, 몇 도 수준이라 제한하기 쉽고, 진행도 s가 명시적이라 기억이 없는 정책도 비드 진행 정도를 알 수 있습니다. 고전 제어기 위에 학습 보정을 얹는 Residual RL, 숙련공의 속도 조정만 배워 로봇에 옮긴 용접 연구(Liu & Zhang, IEEE T-ASE 2017)가 같은 구조입니다.
- **바꿀 때:** 끝에서 끝까지 학습으로 가면 행동이 절대 토치 자세가 되고, 사람 보정을 이음매 좌표계에서 더하는 공유 제어 방식도 다시 설계해야 합니다.

### 이음매 경로 계산: 모재 CAD + depth 카메라

- **채택:** 모재의 형상과 크기로 CAD 경로를 만들고, 셀에 고정한 depth 카메라 점군에 CAD를 정합(ICP)해 실제 좌표에 맞춥니다. 학습 데이터에서는 ICP를 직접 돌리는 대신 실제 경로에 ICP 잔차 오차를 분포로 더해 추정 경로를 만듭니다.
- **대안:**

| 방법 | 필요한 데이터 | 잡는 오차 | 한계 |
| --- | --- | --- | --- |
| 텔레옵 교시 | 시작점·끝점의 토치 끝 자세 | 놓인 위치 | 부품마다 다시 찍어야 함 |
| 터치 센싱 | 용접기 접촉 신호 + 토치 끝 자세 | 놓인 위치·치수 | 느림, 접촉 감지 용접기 필요 |
| 레이저 라인 추적 | 레이저 단면 프로파일 | 위 전부 + 열변형 (용접 중) | 센서가 비쌈 |
| 아크 센싱 | 용접 전류·전압 + 위빙 위상 | 좌우·높이 편차 (용접 중) | 위빙과 옆벽 있는 이음만 |

- **이유:** 추가 장비 없이 부품마다 자동으로 경로를 얻고, 학습 데이터의 ICP 잔차 범위를 실제 ICP 오차에 맞추면 학습 데이터의 보정값 정답(실제 경로 − 추정 경로)이 학습과 추론에서 같은 분포가 됩니다. ICP를 구현하기 전에도 데이터를 만들 수 있습니다.
- **위험:** 저가 depth 카메라는 작업 거리에서 mm 단위 오차가 있어 빠듯합니다(일반 사양 기준 대략치). 정확도를 먼저 재고, 모자라면 터치 센싱으로 보완하는 것을 권장합니다. 열변형은 용접 중 손목 depth 카메라 단면으로 봅니다. 학습 데이터의 ICP 잔차 범위가 실제보다 작으면 정책이 큰 오차를 못 배우므로, 시편별 ICP 오차를 재서 맞춥니다.
- **바꿀 때:** 하위 층에 넘기는 형식(경로 p(s), 이음매 좌표계, 진행도 s, 틈새 폭)이 같으면 정책은 그대로 쓸 수 있습니다. 다만 경로가 달라지면 학습 데이터의 보정값 정답도 다시 계산해야 합니다.

### 용접 중 이음매 관측: 손목 depth 카메라 단면

- **채택:** 토치 옆에 근거리 depth 카메라를 달아 토치 앞 이음매 단면 패치를 재고, 두 판 면에 평면을 맞춥니다. 두 평면의 교선(뿌리선)에서 좌우·높이 편차를, 두 평면이 만드는 이음매 좌표계에서 작업각·진행각 어긋남을 구하고, 틈새 폭과 함께 진행 거리 기준 버퍼로 정책에 줍니다. 시뮬에서는 패치의 판 면 점에 점마다 노이즈와 측정 구멍을 넣고 같은 평면 맞춤을 합니다. 실제 카메라 처리도 뿌리 위치를 두 직선(평면)의 교점으로 구하므로 판 기울기는 같은 맞춤에서 나옵니다.
- **전제:** 실기 검증은 실제 용접이 아니라 아크 없는 시연 환경(시편, 팔로워 암, 배경)입니다. 실물 opti3는 제공되지 않아, 시뮬에서 학습한 정책을 관절 구성이 다른 팔로워 암에서 검증합니다. 레이저 라인 센서와 아크에 강한 카메라는 없고, 용접기 전류 신호를 쓸 수 있는지도 모릅니다.

| 대안 | 방식 | 고르지 않은 이유 |
| --- | --- | --- |
| 레이저 라인 센서 | 토치 앞 레이저 단면 프로파일 | 실기에 달 계획이 없음 |
| 아크 센싱 | 위빙 중 용접 전류 변화로 편차를 읽음 | 시연에 아크가 없고 전류 신호도 불확실 |
| 필터 카메라 | 아크 빛을 거른 영상 | 장비가 없고 시연에는 아크가 없음 |
| RGB 이음매 검출 | 영상에서 이음매 선을 찾아 숫자로 바꿈 | 조명과 배경에 따라 검출이 흔들림 |
| RGB 영상 직접 입력 | 영상을 그대로 정책에 넣음 | 시뮬과 실기의 배경·조명 차이가 커서 큰 도메인 랜덤화와 많은 데이터가 필요 |
| 뿌리 위치만 (좌우·높이·틈새) | 단면에서 뿌리 점 위치만 정책에 줌 | 작업각(이음매 축 둘레 회전)은 뿌리 위치를 바꾸지 않아 정책이 배울 단서가 없음. T 필릿 첫 한 바퀴에서 작업각 보정이 보정 0보다 15% 나빴고, 판 면 기울기를 넣자 작업각 70%, 진행각 64% 좋아짐(운동학 데이터 66개) |
| 각도를 행동에서 빼고 추정 경로 좌표계 그대로 | 정책은 좌우·높이·속도·위빙만 냄 | 국부 변형(잔류 각변형, 휨, 비틀림)으로 생기는 각도 어긋남을 자동으로 못 잡음 |

- **이유:** depth는 형상만 재므로 배경과 조명이 달라도 시뮬과 실기 입력이 비슷하고, 이미 만든 센서 모델과 오차별 단독 검증을 그대로 쓸 수 있습니다.
- **위험:** 근거리 depth 카메라는 금속 반사면에서 측정 구멍이 생기고 최소 측정 거리가 있어 장착 위치가 제한됩니다. 실제 카메라로 시연 시편의 단면 정확도와 실패율을 재서 시뮬 노이즈를 맞춥니다.
- **바꿀 때:** 실제 아크 용접으로 가면 depth 카메라가 아크 빛과 연기에 가려지므로 레이저 라인 센서나 아크 센싱으로 바꿉니다. 정책 입력은 같은 단면 편차 형태라 센서 모델만 바꿔 데이터를 다시 만들면 됩니다.

### 이음매 시작 구간 사각지대: 용접 전 스캔

- **채택:** 아크를 켜기 전에 손목 카메라로 이음매 시작 30 mm를 한 번 훑고, 그 단면으로 거리 버퍼를 미리 채웁니다. 단면은 토치 앞 30 mm에서만 재기 때문에, 토치를 시작점에 놓고 출발하면 시작 30 mm는 용접 내내 보이지 않습니다. 시뮬에서는 같은 평면 맞춤 모델(노이즈, 측정 실패 포함)로 0.5 mm 간격 단면을 재서 넣습니다.
- **검토한 대안:** 시작점 뒤 30 mm에서 아크 없이 출발(리드인)은 용접과 같은 자세·거리로 재서 노이즈가 학습 데이터와 같지만, 시작점 뒤에 빈 공간이 필요하고 용접 속도로 6초가 더 걸립니다. 그대로 두기는 시작 구간 오차를 한계로 받아들이는 것입니다.
- **이유:** 남은 높이 오차를 나눠 보니 점 노이즈와 제어 주기는 거의 영향이 없고, 높이 제곱오차의 84%가 시작 30 mm에 몰려 있었습니다. 첫 가접이 이 구간에 있어서입니다. 스캔을 넣으면 버퍼 값을 그대로 쓰는 규칙만으로 높이 RMS가 0.50에서 0.21 mm로 줄었습니다(운동학 시험 59개, [learning/README.md](../learning/README.md)). 시작점 뒤 공간이 없는 코너·맞대기·파이프 시편에도 쓸 수 있습니다.
- **위험:** 스캔 자세가 용접 자세와 달라 측정 노이즈가 다를 수 있고, 너무 높이 들면 근거리 카메라의 최소 측정 거리와 정밀도가 문제가 됩니다. 실제 카메라로 스캔 자세의 노이즈를 따로 재서 맞춥니다. 남은 0.21 mm는 잰 뒤 모재가 움직이는 오차(갑자기 튐, 서서히 밀림, 세로 휨)라 스캔으로 줄지 않습니다.
- **바꿀 때:** 시작점 뒤 공간이 있는 시편에서는 리드인으로 바꿔도 시뮬 결과는 같습니다. 설정은 `sensors.prescan_mm`(0이면 스캔 없음).

### 정책 조건 입력: 직선·위빙 모드 + 진행도 s, WPS 고정

- **채택:** 직선/위빙 모드(원-핫)와 진행도 s를 상태 뒤에 붙여 넣습니다. 공칭 용접 조건(WPS: 진행 속도, 위빙 폭·주기, 토치 각도)은 고정값으로 시작해 기본 궤적에만 쓰고 조건 입력에 넣지 않습니다.
- **대안:** 모든 단계를 단계 ID로 구분하는 정책 하나. 학습 가능한 단계 임베딩을 별도 토큰으로 넣기. 공칭 WPS 값을 조건 입력으로 넣고 에피소드마다 뽑아 학습하기.
- **이유:** 학습하는 단계가 용접 하나뿐이라 단계 ID는 정보가 없습니다. 진행도 s는 비드가 어디까지 왔는지 알려 주고, 원-핫은 모델 코드 수정 없이 들어갑니다. WPS를 고정하면 시편군마다 필요한 데이터가 줄고, 시뮬과 시연에는 비드가 없어 WPS를 바꿔도 결과를 비교할 수 없습니다.
- **확인 방법:** 같은 관측에 모드만 바꿔 넣어 행동이 달라지는지 봅니다. 안 달라지면 모델이 조건을 무시하는 것입니다.
- **바꿀 때:** 학습 단계가 늘거나(예: 아크를 정책이 내기로 할 때) 다층 용접처럼 장면이 비슷한데 할 일이 다른 경우가 생기면 단계 ID를 추가합니다. 단계별 데이터 균형을 맞춰야 합니다. 여러 WPS를 한 정책으로 다루려면 WPS 값을 조건 입력에 붙이고, 에피소드마다 WPS를 뽑아 데이터를 다시 만듭니다.

### 정책 모델: MLP/GRU 행동 복제

- **채택:** 저차원 관측(손목 depth 단면 편차·판 면 기울기 버퍼, 진행도 s, 모드)을 받아 이음매 기준 보정값을 매 주기 한 스텝씩 내는 작은 MLP 또는 GRU를 행동 복제로 학습해 고정합니다. 시뮬 전문가 DAgger는 보류했습니다(아래 "보류한 기능"). 잔차 모델도 같은 형태의 작은 모델입니다.
- **대안:** ACT, Diffusion Policy, 사전학습 VLA (아래 표).
- **이유:** 입력이 영상이 아니라 수십 개 숫자이고 출력이 수 mm, 몇 도 범위의 보정값이라, 영상과 긴 행동 묶음을 다루려고 만든 큰 모델이 필요 없습니다. 위빙 패턴은 기본 궤적이 내므로 정답이 여럿으로 갈리는 경우가 적어 Diffusion Policy의 장점이 작습니다. 매 주기 한 스텝씩 내므로 사람 보정에 바로 반응하고, 학습과 추론이 가벼워 대량 에피소드 실험이 빠릅니다. 단면 편차가 추정 경로 기준이라 정책 출력이 다음 관측을 바꾸지 않으므로, 행동 복제만으로도 닫힌 루프 오차가 열린 루프 오차와 거의 같습니다(T 필릿 운동학 330개, MLP 좌우 0.21 mm 대 0.21 mm).
- **위험:** 시간 문맥이 필요한 행동을 MLP가 못 배울 수 있습니다. 진행 거리 기준 버퍼로 부족하면 GRU로 바꿉니다. 카메라 영상을 입력에 넣거나 숙련공 손기술처럼 정답이 여럿인 행동을 배우려면 이 모델로는 모자랍니다.
- **바꿀 때:** 입출력(이음매 기준 보정값)이 같아 모델만 바꿔 같은 데이터로 학습할 수 있습니다. ACT는 행동 묶음을 짧게 실행(`n_action_steps` 10\~20)해야 사람 보정에 빨리 반응하고, 넘겨받았다 돌려줄 때 temporal ensembling 버퍼도 버려야 합니다. Diffusion Policy는 개입 중에도 관측 큐를 갱신하고, 제어 주기를 높이면 데이터셋을 10 Hz로 낮춰 학습합니다. VLA는 사전학습에 용접이 거의 없어 이음매 종류와 영상 입력이 늘 때 검토합니다.

| 후보 | 데이터 | 관측 이력 | 위빙(정답이 여럿) | 불확실성 | 추론 |
| --- | --- | --- | --- | --- | --- |
| MLP/GRU 행동 복제 (채택) | 시뮬 전문가 에피소드 수백 개 | 진행 거리 버퍼, GRU는 은닉 상태 | 기본 궤적이 위빙을 내 정답이 거의 하나 | 없음 (앙상블로 추정 가능) | 매우 빠름, CPU로 충분 |
| ACT | 데모 50\~100개 | 없음 | 평균으로 뭉개질 수 있음 | 없음 | 빠름 |
| Diffusion Policy | 데모 100\~200개 | 2프레임(10 Hz 기준) | 강함 | 샘플 퍼짐으로 측정 | 느림, DDIM 10단계로 실시간 |
| 사전학습 VLA (π0.5, SmolVLA, GR00T) | 사전학습 + 수십\~수백 | 모델마다 다름 | 강함 | 샘플링 가능 | 중간, GPU 필요 |

- 데이터 수와 추론 속도는 일반적으로 보고된 대략치입니다.

### 보정 정책 학습 데이터: 시뮬 규칙 전문가 데이터만

- **채택:** 보정 정책은 Isaac Sim에서 모재 오차를 섞은 규칙 전문가 에피소드로만 학습한 뒤 고정합니다. 배우는 것은 기하 보정(좌우·높이 편차, 이음매를 따르는 토치 각도)과 틈새에 따른 위빙·속도 규칙입니다. 개입 데이터는 기본 정책에 쓰지 않고 잔차 모델만 학습합니다. 실기 시연 미세조정은 보류한 기능으로 남겨 둡니다.
- **입력 제한:** 실기 데이터로 다시 맞추지 않으므로 입력은 시뮬과 실기에 같은 의미로 있는 값만 씁니다. 손목 depth 카메라 단면 편차와 판 면 기울기, 진행도 s, 직선·위빙 모드입니다. 카메라 영상은 시뮬과 실기의 배경·조명 차이가 커서 입력에서 뺍니다. 이음매 좌표계 토치 자세도 기록만 하고 입력에서 뺍니다. 기록에서 지금 토치 자세는 직전 전문가 명령과 거의 같아, 넣으면 정책이 단면 대신 직전 명령을 따라 하는 지름길을 배웁니다. 단면 편차는 잴 때의 토치 자세로 이미 추정 경로 기준으로 바꿔 두므로 따로 넣지 않아도 됩니다.
- **대안:** 시뮬 사전학습 뒤 실기 아크 텔레옵 시연으로 미세조정(시뮬 데이터 일부 혼합). 실기 텔레옵 시연만으로 학습. 시뮬에서 텔레옵으로 시연을 모으고 후처리. 개입 데이터로 기본 정책까지 미세조정. 토치 자세를 입력에 넣기(T 필릿 운동학 데이터 66개로 두 번 비교했고, 두 번 모두 닫힌 루프 높이 개선이 줄었음: 프로파일 없을 때 69%에서 62%, 있을 때 68%에서 57%).
- **이유:** 실기 검증도 아크 없는 시연 환경이라 실기 아크 데이터를 얻을 수 없습니다. Isaac Sim에는 용융지·비드·열이 없어 시뮬이 가르칠 수 있는 것은 기하 보정뿐이고, 그 범위에서는 실제 경로를 아는 규칙 전문가가 손떨림 없는 정답을 원하는 만큼 만들어 줍니다. 시뮬 텔레옵은 후처리하고 나면 규칙 데이터와 거의 같아져 수집 비용만 큽니다. 개입 데이터를 잔차 모델에만 쓰는 것은 아래 "개입 데이터 활용" 결정과 같습니다.
- **한계:** 정책은 규칙 전문가를 넘지 못합니다. 용융지를 보고 속도와 위빙을 바꾸는 공정 기술, 위빙 끝에서 머무는 것 같은 숙련공의 손기술은 배우지 않습니다. 실기에서 적응하는 길은 개입 데이터로 배우는 잔차 모델뿐이고, 그마저 사람 권한 축(높이·좌우·토치 각도)만 고칩니다. 진행 속도와 위빙은 규칙 전문가 값 그대로라, 틈새 → 위빙·속도 규칙은 실제 아크 용접으로 가기 전에 WPS 값으로 바꿔야 합니다.
- **위험:** 시뮬 오차 분포와 depth 단면 센서 모델이 실제와 다르면 엉뚱한 범위를 배웁니다. 오차 범위는 실측으로 맞추고, 구현은 오차별 단독 검증으로 확인합니다([모재 오차 모델링 계획](https://claude.ai/artifact/UftNfNDdFX5SXsranrBDFk)).
- **바꿀 때:** 실기 시연 미세조정을 넣는 방법은 아래 "보류한 기능"에 있습니다. 카메라 영상을 입력에 넣으려면 배경·조명 도메인 랜덤화가 필요합니다. 개입 데이터로 기본 정책도 고치려면 "개입 데이터 활용"의 대안(같은 모델 재학습)으로 바꿉니다. 위빙 끝에서 머무는 시간처럼 위빙 위상에 따라 달라지는 행동을 넣으면 토치 자세 대신 위빙 위상(sin, cos)을 입력에 더합니다.

## 사람 개입과 텔레옵

### 사람 개입: 공유 제어

- **채택:** 모델은 개입 중에도 멈추지 않고 추론을 이어 가며, 사람 보정은 이음매 좌표계에서 모델 보정에 더합니다.
- **대안:** 넘겨받기. 클러치를 누르면 정책 명령을 끊고 사람이 조종하며, 복귀할 때 남은 행동 묶음을 버리고 새로 추론합니다.
- **이유:** 사람이 조작하는 동안에도 모델이 "생각"하며 반응하기를 원했습니다. 넘겨받기에서는 정책 명령을 끊으므로, 기억이 없는 정책은 개입 중 추론이 사실상 정지와 같습니다. 가장 가까운 연구인 CR-DAgger(NeurIPS 2025)에서 보정을 더하는 방식이 넘겨받기보다 성공률이 약 45% 높았습니다.
- **바꿀 때:** 넘겨받기로 가면 모든 축의 사람 권한을 100%로 두는 것과 같아서 구조는 그대로 쓸 수 있습니다. 다만 잔차 모델의 학습 데이터(사람 델타)는 얻을 수 없게 됩니다.

### 개입 데이터 활용: 작은 잔차 모델

- **채택:** 보정 정책은 시뮬 데이터로 학습한 뒤 고정하고, 공유 제어 중 모인 사람 보정(델타)으로 작은 잔차 모델을 학습합니다.
- **대안:** 개입 데이터를 시연에 합쳐 같은 모델을 다시 학습(HG-DAgger 방식, 정답은 모델 보정 + 사람 보정 합계). 두 방식을 모두 구현해 시뮬에서 비교.
- **이유:** CR-DAgger에서 사람 보정만 배우는 작은 잔차 모델이 같은 모델 재학습보다 훨씬 나았고, 보정 에피소드 50\~100개로 충분했습니다. 다만 접촉 작업 결과라 용접에서는 검증되지 않았습니다.
- **형태:** 작은 MLP(필요하면 GRU)로 행동 복제하고, 입력은 보정 정책과 같은 관측에 보정 정책 출력을 더한 것, 출력은 사람 권한 축(높이·좌우·각도) 보정량입니다. 출력은 몇 mm, 몇 도로 제한하고, 개입 없는 구간도 섞어 아무 때나 보정하지 않게 합니다. 정답이 사람이라 시뮬 전문가처럼 아무 상태에서나 라벨을 붙일 수 없으므로 별도 DAgger는 없고, 정책이 실행하고 사람이 필요할 때만 고치는 수집 방식 자체가 HG-DAgger와 같은 구조입니다.
- **정답:** 그 시점에 적용 중인 사람 보정이고, 클러치를 놓은 뒤 유지되는 오프셋도 포함합니다. 작업자가 오프셋 초기화 버튼을 누르면 오프셋이 짧은 램프로 0이 되고 정답도 0이 됩니다. 대안은 클러치 ON 동안의 델타만 정답으로 두고 놓은 뒤는 0으로 넣는 방식인데, 그러면 로봇은 유지된 오프셋으로 움직이는데 모델은 보정이 필요 없다고 배워 실행과 정답이 어긋납니다.
- **바꿀 때:** 같은 모델 재학습으로 가면 로봇 목표에서 잔차 항이 빠지고, 정답을 실행된 합계로 바꿉니다. 개입 구간 비중을 높이고 개입 직전 약 2초를 빼는 규칙(Sirius)은 두 방식 모두 적용됩니다.

### 축별 권한과 놓은 뒤 처리

- **채택:** 높이·좌우·토치 각도는 사람, 진행과 위빙은 모델이 맡습니다. 클러치를 놓으면 사람 보정을 오프셋으로 유지하고, 필요 없어지면 작업자가 오프셋 초기화 버튼으로 짧은 램프를 거쳐 0으로 되돌립니다.
- **대안:** 다른 축 배분(예: 진행 속도도 사람). 놓은 뒤 사람 보정을 서서히 줄이기.
- **이유:** 숙련공이 주로 고치는 것은 높이와 각도이고, 진행과 위빙을 모델이 이어 가야 공유 제어의 의미가 있습니다. 오프셋을 유지하면 토치를 2 mm 올린 의도가 놓은 뒤에도 남습니다. 자동 감쇠 대신 초기화 버튼을 두면 오프셋을 언제 없앨지 작업자가 정하고, 그 시점이 기록되어 잔차 모델 정답도 분명해집니다.
- **바꿀 때:** 권한 비율과 감쇠 속도는 설정값이라 구조 변경 없이 바꿀 수 있습니다. 감쇠는 시뮬에서 비교해 보고 정하면 됩니다.

### 제어 주체 중재: 클러치와 축별 권한 규칙

- **채택:** 사람과 모델 중 누가 조종할지는 클러치와 축별 권한 규칙이 정합니다.
- **대안:** Jev가 사람 입력, 정책 출력, 이음매 감지 결과를 보고 "사람 우선 / 모델 우선 / 블렌딩 / 정지" 중 하나를 고름.
- **이유:** 규칙으로 두면 사람이 누른 클러치가 항상 그대로 통합니다. Jev는 판단에 0.1\~0.6초가 걸려 즉각적인 주도권 전환에 맞지 않습니다.
- **바꿀 때:** Jev에 중재를 맡기려면 Jev 연결(상태 요약과 선택지)을 새로 만들고 중재 모드를 선택지로 넣으며, 어떤 경우에도 클러치가 우선하도록 해야 합니다.

### 텔레옵 방식: TCP(토치 끝)

- **채택:** 리더 손끝의 움직임을 토치 끝이 따라가는 TCP 방식입니다.
- **대안:** 관절 방식. opti3 팔 모양이 리더 팔 모양을 따라갑니다.
- **비교:** 관절 방식은 IK가 없어 도달 범위 경계의 정지가 없고 단순합니다. 대신 opti3 팔이 약 2.5배 길어 리더 10 cm가 토치 약 25 cm가 되고, 토치 길이와 손목 구조가 달라 토치 각도가 정확히 맞지 않으며, 클러치로 리더를 다시 잡을 수 없습니다.
- **이유:** 용접은 곧은 선을 일정한 토치 각도로 따라가야 하고, 이음매 좌표 보정과 사람 보정 더하기가 모두 TCP 변화량을 전제로 합니다.
- **바꿀 때:** 관절 방식에서는 사람 보정을 FK로 토치 변화량으로 바꿔 이음매 좌표계에 넣어야 하고, 클러치 ON 때 opti3가 리더 자세까지 천천히 이동하는 단계가 필요합니다.

## 미정 장치, 보류한 기능, 참고 자료

### 보류한 기능

지금 구조에는 넣지 않았지만, 구조를 바꾸지 않고 나중에 붙일 수 있는 기능입니다.

- **사람 동작 다듬기:** Diffusion Policy처럼 노이즈 제거 방식의 모델이라면, 사람 동작에 노이즈를 일부 섞고 모델이 걷어 내게 해 사람 의도를 숙련 동작으로 다듬을 수 있습니다 ([Yoneda et al., RSS 2023](https://arxiv.org/abs/2302.12244)). 지금 정책(MLP/GRU)은 노이즈 제거 방식이 아니어서, Diffusion Policy로 바꿀 때 검토합니다.
- **리더 햅틱 가이드:** 리더의 Feetech 서보 토크로 모델이 가려는 쪽을 약하게 알려 줍니다. 붙이더라도 로봇 정지는 모델과 어긋났다는 이유가 아니라 안전 기준으로만 합니다.
- **검출 기반 자동 시작:** 작업 시작 항목의 "바꿀 때"를 참고하세요.
- **실기 시연 미세조정:** 시뮬로 학습한 보정 정책을 실기 아크 텔레옵 시연으로 미세조정해, 용융지를 보고 속도·위빙을 바꾸는 공정 기술과 숙련공의 손기술(위빙 끝에서 머무는 동작 등)을 더합니다. 접근부터 후퇴까지 전체 에피소드를 텔레옵으로 녹화하고 시점별 단계 라벨, 직선/위빙 모드, 아크 ON/OFF 시점을 기록합니다. 용접 단계 구간을 이음매 기준 보정값으로 바꿔 시뮬 데이터를 일부 섞어 미세조정한 뒤 다시 고정합니다. 섞지 않으면 기하 보정을 잊기 쉽습니다. 정책 입력은 그대로 두고, 잔차 모델은 새 보정 정책 위에서 다시 학습합니다. 실기 아크 환경이 갖춰지면 검토합니다.
- **시뮬 전문가 DAgger:** 정책이 직접 몬 궤적에 시뮬 규칙 전문가가 정답을 다시 붙여 데이터에 더합니다. T 필릿 운동학 330개에서 섭동을 빼도 결과가 같았고(같은 156개에서 1\~2%p 안), 열린 루프와 닫힌 루프 오차도 거의 같았습니다. 토치 자세를 입력에서 뺀 뒤로는 정책 출력이 관측을 바꾸지 않아 쌓이는 오차가 없기 때문입니다. 토치를 따라 움직이는 카메라 시야를 센서 모델에 넣거나, 정책 출력에 따라 바뀌는 입력을 더하면 검토합니다.

### 실제 로봇으로 옮길 때 정할 장치

- **클러치와 시작 트리거 장치:** 풋페달, 리더 손잡이 버튼, PLC 신호 중에서 고릅니다. 시뮬에서는 Enter 키를 클러치로 씁니다.
- **손목 depth 카메라 기종:** 최소 측정 거리, 시연 시편에서의 단면 정확도, 금속 반사로 생기는 측정 구멍을 재서 고릅니다. 잰 값으로 시뮬 단면 센서의 노이즈와 실패율을 맞춥니다.
- **실기 검증 팔로워 암:** LeBot을 검토 중입니다. 정해지기 전까지는 opti3를 기준으로 진행하고, 정해지면 그 URDF로 시뮬에서 먼저 같은 정책을 돌려 봅니다.
- **실제 아크 용접의 이음매 센서:** 실기 검증은 아크 없는 시연이라 손목 depth 카메라로 충분하지만, 실제 아크 용접에서는 depth 카메라가 아크 빛과 연기에 가려집니다. 그때는 레이저 라인 센서나 아크 센싱으로 바꿉니다(위 "용접 중 이음매 관측").
