# 용접 로봇 설계 결정

## 한눈에 보기

아키텍처를 바꿀 때 참고하도록, 주제마다 채택한 안, 검토한 대안, 이유, 바꾸면 영향받는 곳을 모았습니다. 현재 설계 자체는 [용접 로봇 아키텍처](../README.md)에 있습니다.

| 주제 | 채택한 안 | 검토한 대안 |
| --- | --- | --- |
| 작업 시작 | 명시적 시작 트리거, 클러치와 분리 | 클러치 겸용, 검출 모듈이 자동 시작 |
| 단계 전이 판단 | 규칙 상태기계 | Jev가 처음부터 모든 전이 결정, 규칙으로 시작한 뒤 Jev와 비교 |
| 전이 자율 수준 | 트리거 이후 모든 전이 자동 | 아크 ON은 사람 승인 |
| 아크 ON/OFF와 크레이터 | 단계 전이 + 용접기 설정 | 정책 행동에 포함 |
| 계층 구조 | 경로는 계산, 정책은 보정만 학습 | 정책이 경로까지 학습 |
| 이음매 경로 계산 | 모재 CAD + depth 카메라 정합 | 텔레옵 교시, 터치 센싱, 레이저 추적, 아크 센싱 |
| 용접 중 이음매 관측 | 손목 depth 카메라 단면 (아크 없는 시연 환경 기준) | 레이저 라인, 아크 센싱, 필터 카메라, RGB 이음매 검출, RGB 영상 직접 입력 |
| 정책 조건 입력 | 직선·위빙 모드 + 진행도 s | 전체 단계 ID |
| 정책 모델 | 미정 | ACT, Diffusion Policy, 사전학습 VLA |
| 보정 정책 학습 데이터 | 시뮬 규칙 전문가 데이터만으로 학습 (실기 시연 미세조정은 보류) | 실기 시연 미세조정 추가, 실기 시연만, 시뮬 텔레옵 시연, 개입 데이터로 미세조정 |
| 사람 개입 | 공유 제어 (모델 보정에 사람 보정을 더함) | 넘겨받기 (개입 중 정책 정지) |
| 개입 데이터 활용 | 작은 잔차 모델 학습 | 같은 모델 재학습, 둘 다 비교 |
| 축별 권한과 놓은 뒤 처리 | 높이·좌우·각도는 사람, 진행·위빙은 모델, 오프셋 유지 | 다른 배분, 서서히 감쇠 |
| 제어 주체 중재 | 클러치 + 축별 권한 규칙 | Jev가 중재 |
| 텔레옵 방식 | TCP(토치 끝) | 관절 방식 |
| 실제 로봇 장치 | 미정 | 클러치·트리거: 풋페달, 손잡이 버튼, PLC 신호. 실기 검증 팔로워 암: LeBot 검토 중 |

## 작업 흐름

### 작업 시작: 명시적 시작 트리거

- **채택:** 사람이 시작 트리거를 눌러야만 작업이 시작됩니다. 클러치는 사람 보정을 켜고 끄는 역할만 합니다.
- **대안:** 클러치를 시작 신호로 겸용하기. 트리거 없이 검출 모듈이 시작 시점을 정하기.
- **이유:** 클러치를 겸용하면 용접공이 토치 위치만 잡고 클러치를 떼는 순간 작업이 시작됩니다. 자동 시작은 아크의 빛, 흄, 화상 위험 때문에 현장에서도 대부분 사람이 확인합니다.
- **바꿀 때:** 자동 시작으로 가려면 상위 층에 미용접 이음매 검출(비드 유무 구분)과 시작 조건 확인(모재 고정, 셀 안에 사람 없음)이 더 필요합니다. 중간안은 검출 모듈이 "준비됨"을 알리고 작업자가 한 번 누르는 방식입니다.

### 단계 전이 판단: 규칙 상태기계

- **채택:** 대기 → 접근 → 아크 ON → 용접 → 크레이터 → 후퇴 사이의 전이를 코드의 규칙 상태기계가 정합니다. 조건은 시작 트리거, 시작점 도달, 점화 확인, 진행도 s = 1(경로 끝), 크레이터 시간 종료이고, 용접 중 추종 오차 초과·이음매 분실·IK 실패가 이어지면 아크를 끄고 일시정지합니다.
- **대안:** 처음부터 Jev가 모든 전이를 고르기. 규칙으로 시작하고 Jev는 같은 입력으로 shadow mode에서 비교한 뒤 이기면 교체.
- **이유:** 학습하는 단계가 용접 하나뿐이고, 전이 입력(시작점 도달, 점화 확인, 진행도, 추종 오차)은 사람이 보고 바로 고를 수 있는 수준이라 규칙으로 충분합니다. 규칙은 결정론적이라 시뮬에서 검증하기 쉽고, 외부 API 접근 권한, 네트워크 지연과 단절 대비, 용접에서의 확률 보정 검증 같은 Jev의 선행 조건이 없어집니다.
- **위험:** 전이 임계값(위치·자세 오차, 추종 오차, 이음매 분실 시간)은 Isaac Sim 로그로 정하고 실기에서 다시 맞춰야 합니다. 전류 파형이나 용융지 이상처럼 사람이 한눈에 판단하기 어려운 신호가 늘면 규칙이 복잡해집니다.
- **바꿀 때:** Jev를 다시 넣으려면 상태를 수치와 플래그로 요약하고(`tracking_error_high`처럼 임계값은 코드가 계산), 현재 단계에서 허용된 전이만 선택지로 넣으며, 선택지별 결과(도달 가능 여부, 남은 거리)는 코드가 계산해 넘깁니다(arXiv 2610.01834). 응답 전이나 단절 때는 현재 단계를 유지하고, 신뢰도가 낮으면 현재 단계 유지나 일시정지를 택합니다. Isaac Sim 로그로 정확도를 확인한 뒤 shadow mode에서 규칙과 비교합니다. 자세한 설계는 [Jev 의사결정 모델 설계 고려사항](https://claude.ai/artifact/StWcQDXxRGm56MEgxkNRmt)에 있습니다.

### 전이 자율 수준: 트리거 이후 모두 자동

- **채택:** 시작 트리거 이후 아크 ON을 포함한 모든 전이를 사람 승인 없이 실행합니다. 사람은 클러치와 하드 인터록으로 개입합니다.
- **대안:** 아크 ON처럼 되돌릴 수 없는 전이는 상태기계가 제안만 하고 사람이 버튼으로 확정. 일시정지·핸드오버 같은 안전 쪽 전이만 즉시 실행.
- **이유:** 시작은 사람이 확인하고, 그 뒤 안전은 클러치와 하드 인터록이 보장합니다. 점화 실패나 추종 오차 초과처럼 조건이 어긋나면 사람에게 넘기는 대신 일시정지나 후퇴 같은 안전 쪽 전이를 택합니다.
- **바꿀 때:** 승인 방식으로 가려면 승인 버튼 입력과 "승인 대기" 상태를 추가하고, 조건이 어긋날 때의 처리를 "사람에게 넘김"으로 바꾸면 됩니다.

### 아크 ON/OFF와 크레이터: 단계 전이 + 용접기 설정

- **채택:** 상태기계가 아크 ON 또는 크레이터 단계로 넘기면 코드가 용접기에 명령을 보내고, 점화 순서와 크레이터 전류·시간은 용접기 설정값을 씁니다.
- **대안:** 정책이 아크 ON/OFF와 크레이터 처리를 행동으로 출력.
- **이유:** 되돌릴 수 없는 아크 명령을 결정론적으로 두고, 학습 범위를 용접 단계 하나로 유지합니다. 대안은 점화 뒤 용융지가 생길 때까지 머무는 타이밍이나 끝점 비드를 보고 크레이터 시간을 조절하는 숙련 동작을 배울 수 있지만, 점화 타이밍 오류와 경계에서의 ON/OFF 떨림 위험이 생깁니다.
- **바꿀 때:** 정책 행동에 아크 명령을 넣고, 학습 단계를 아크 ON·용접·크레이터 셋으로 늘리며, 조건 입력에 단계 ID를 추가합니다. 시연에는 용접공의 아크 명령을 정답으로 기록해야 하고, 출력에 최소 유지 시간이나 히스테리시스를 두며, 크레이터 전류·시간은 용접기 설정 범위 안으로 제한합니다. 하드 인터록은 그 세 단계 밖의 점화를 막아야 합니다.

## 경로와 정책

### 계층 구조: 경로는 계산하고 보정만 학습

- **채택:** 상위 층은 이음매 경로를 고전 방식으로 계산하고, 하위 층 정책은 그 경로 기준의 보정값만 학습합니다.
- **대안:** 정책이 카메라 입력만으로 토치 경로까지 학습(끝에서 끝까지).
- **이유:** 위치 정확도는 CAD와 센서가 책임지고, 정책은 경로 대비 보정만 배우므로 데이터가 적게 듭니다. 출력이 수 mm, 몇 도 수준이라 제한하기 쉽고, 진행도 s가 명시적이라 기억이 없는 정책도 비드 진행 정도를 알 수 있습니다. 고전 제어기 위에 학습 보정을 얹는 Residual RL, 숙련공의 속도 조정만 배워 로봇에 옮긴 용접 연구(Liu & Zhang, IEEE T-ASE 2017)가 같은 구조입니다.
- **바꿀 때:** 끝에서 끝까지 학습으로 가면 행동이 절대 토치 자세가 되고, 사람 보정을 이음매 좌표계에서 더하는 공유 제어 방식도 다시 설계해야 합니다.

### 이음매 경로 계산: 모재 CAD + depth 카메라

- **채택:** 학습과 추론 모두 모재의 형상과 크기로 CAD 경로를 만들고, depth 카메라 점군에 CAD를 정합(ICP)해 실제 좌표에 맞춥니다.
- **대안:**

| 방법 | 필요한 데이터 | 잡는 오차 | 한계 |
| --- | --- | --- | --- |
| 텔레옵 교시 | 시작점·끝점의 토치 끝 자세 | 놓인 위치 | 부품마다 다시 찍어야 함 |
| 터치 센싱 | 용접기 접촉 신호 + 토치 끝 자세 | 놓인 위치·치수 | 느림, 접촉 감지 용접기 필요 |
| 레이저 라인 추적 | 레이저 단면 프로파일 | 위 전부 + 열변형 (용접 중) | 센서가 비쌈 |
| 아크 센싱 | 용접 전류·전압 + 위빙 위상 | 좌우·높이 편차 (용접 중) | 위빙과 옆벽 있는 이음만 |

- **이유:** 추가 장비 없이 부품마다 자동으로 경로를 얻고, 학습과 추론의 경로가 같은 방식이라 학습 데이터의 보정값 정답(실제 경로 − 추정 경로)이 일관됩니다.
- **위험:** 저가 depth 카메라는 작업 거리에서 mm 단위 오차가 있어 빠듯합니다(일반 사양 기준 대략치). 정확도를 먼저 재고, 모자라면 터치 센싱으로 보완하는 것을 권장합니다. 열변형은 용접 중 손목 depth 카메라 단면으로 봅니다.
- **바꿀 때:** 하위 층에 넘기는 형식(경로 p(s), 이음매 좌표계, 진행도 s, 틈새 폭)이 같으면 정책은 그대로 쓸 수 있습니다. 다만 경로가 달라지면 학습 데이터의 보정값 정답도 다시 계산해야 합니다.

### 용접 중 이음매 관측: 손목 depth 카메라 단면

- **채택:** 토치 옆에 근거리 depth 카메라를 달아 토치 앞 이음매 단면을 재고, 좌우·높이 편차와 틈새 폭을 진행 거리 기준 버퍼로 정책에 줍니다. 시뮬에서는 기존 레이저 라인 센서 모델(앞쪽 거리, 노이즈, 측정 실패)을 그대로 쓰고 값만 depth 카메라에 맞춥니다.
- **전제:** 실기 검증은 실제 용접이 아니라 아크 없는 시연 환경(시편, 팔로워 암, 배경)입니다. 실물 opti3는 제공되지 않아, 시뮬에서 학습한 정책을 관절 구성이 다른 팔로워 암에서 검증합니다. 레이저 라인 센서와 아크에 강한 카메라는 없고, 용접기 전류 신호를 쓸 수 있는지도 모릅니다.

| 대안 | 방식 | 고르지 않은 이유 |
| --- | --- | --- |
| 레이저 라인 센서 | 토치 앞 레이저 단면 프로파일 | 실기에 달 계획이 없음 |
| 아크 센싱 | 위빙 중 용접 전류 변화로 편차를 읽음 | 시연에 아크가 없고 전류 신호도 불확실 |
| 필터 카메라 | 아크 빛을 거른 영상 | 장비가 없고 시연에는 아크가 없음 |
| RGB 이음매 검출 | 영상에서 이음매 선을 찾아 숫자로 바꿈 | 조명과 배경에 따라 검출이 흔들림 |
| RGB 영상 직접 입력 | 영상을 그대로 정책에 넣음 | 시뮬과 실기의 배경·조명 차이가 커서 큰 도메인 랜덤화와 많은 데이터가 필요 |

- **이유:** depth는 형상만 재므로 배경과 조명이 달라도 시뮬과 실기 입력이 비슷하고, 이미 만든 센서 모델과 오차별 단독 검증을 그대로 쓸 수 있습니다.
- **위험:** 근거리 depth 카메라는 금속 반사면에서 측정 구멍이 생기고 최소 측정 거리가 있어 장착 위치가 제한됩니다. 실제 카메라로 시연 시편의 단면 정확도와 실패율을 재서 시뮬 노이즈를 맞춥니다.
- **바꿀 때:** 실제 아크 용접으로 가면 depth 카메라가 아크 빛과 연기에 가려지므로 레이저 라인 센서나 아크 센싱으로 바꿉니다. 정책 입력은 같은 단면 편차 형태라 센서 모델만 바꿔 데이터를 다시 만들면 됩니다.

### 정책 조건 입력: 직선·위빙 모드 + 진행도 s

- **채택:** 직선/위빙 모드(원-핫)와 진행도 s를 상태 뒤에 붙여 넣습니다.
- **대안:** 모든 단계를 단계 ID로 구분하는 정책 하나. 학습 가능한 단계 임베딩을 별도 토큰으로 넣기.
- **이유:** 학습하는 단계가 용접 하나뿐이라 단계 ID는 정보가 없습니다. 진행도 s는 비드가 어디까지 왔는지 알려 주고, 원-핫은 모델 코드 수정 없이 들어갑니다.
- **확인 방법:** 같은 관측에 모드만 바꿔 넣어 행동이 달라지는지 봅니다. 안 달라지면 모델이 조건을 무시하는 것입니다.
- **바꿀 때:** 학습 단계가 늘거나(예: 아크를 정책이 내기로 할 때) 다층 용접처럼 장면이 비슷한데 할 일이 다른 경우가 생기면 단계 ID를 추가합니다. 단계별 데이터 균형을 맞춰야 합니다.

### 정책 모델: 미정

아직 정하지 않았습니다. 시뮬 규칙 전문가 데이터로 학습하는 행동 복제 정책이면 현재 인터페이스(이음매 기준 보정값 출력)에 들어갑니다.

| 후보 | 데이터 | 관측 이력 | 위빙(정답이 여럿) | 불확실성 | 추론 |
| --- | --- | --- | --- | --- | --- |
| ACT | 데모 50\~100개 | 없음 | 평균으로 뭉개질 수 있음 | 없음 | 빠름 |
| Diffusion Policy | 데모 100\~200개 | 2프레임(10 Hz 기준) | 강함 | 샘플 퍼짐으로 측정 | 느림, DDIM 10단계로 실시간 |
| 사전학습 VLA (π0.5, SmolVLA, GR00T) | 사전학습 + 수십\~수백 | 모델마다 다름 | 강함 | 샘플링 가능 | 중간, GPU 필요 |

- 지금까지의 추천은 ACT로 기준선을 만들고 같은 데이터로 Diffusion Policy를 비교하는 순서입니다. VLA는 사전학습에 용접이 거의 없어 이음매 종류가 늘 때 검토합니다.
- 모델에 따라 달라지는 곳: ACT는 행동 묶음을 짧게 실행(`n_action_steps` 10\~20)해야 사람 보정에 빨리 반응하고, 넘겨받았다 돌려줄 때 temporal ensembling 버퍼도 버려야 합니다. Diffusion Policy는 개입 중에도 관측 큐를 갱신하고, 제어 주기를 높이면 데이터셋을 10 Hz로 낮춰 학습합니다.
- 데이터 수와 추론 속도는 일반적으로 보고된 대략치입니다.

### 보정 정책 학습 데이터: 시뮬 규칙 전문가 데이터만

- **채택:** 보정 정책은 Isaac Sim에서 모재 오차를 섞은 규칙 전문가 에피소드로만 학습한 뒤 고정합니다. 배우는 것은 기하 보정(좌우·높이 편차, 이음매를 따르는 토치 각도)과 틈새에 따른 위빙·속도 규칙입니다. 개입 데이터는 기본 정책에 쓰지 않고 잔차 모델만 학습합니다. 실기 시연 미세조정은 보류한 기능으로 남겨 둡니다.
- **입력 제한:** 실기 데이터로 다시 맞추지 않으므로 입력은 시뮬과 실기에 같은 의미로 있는 값만 씁니다. 손목 depth 카메라 단면 편차, 토치 자세, 진행도 s, 직선·위빙 모드입니다. 카메라 영상은 시뮬과 실기의 배경·조명 차이가 커서 입력에서 뺍니다.
- **대안:** 시뮬 사전학습 뒤 실기 아크 텔레옵 시연으로 미세조정(시뮬 데이터 일부 혼합). 실기 텔레옵 시연만으로 학습. 시뮬에서 텔레옵으로 시연을 모으고 후처리. 개입 데이터로 기본 정책까지 미세조정.
- **이유:** 지금은 Isaac Sim에서만 작업하고 실기 아크 환경이 없습니다. Isaac Sim에는 용융지·비드·열이 없어 시뮬이 가르칠 수 있는 것은 기하 보정뿐이고, 그 범위에서는 실제 경로를 아는 규칙 전문가가 손떨림 없는 정답을 원하는 만큼 만들어 줍니다. 시뮬 텔레옵은 후처리하고 나면 규칙 데이터와 거의 같아져 수집 비용만 큽니다. 개입 데이터를 잔차 모델에만 쓰는 것은 아래 "개입 데이터 활용" 결정과 같습니다.
- **한계:** 정책은 규칙 전문가를 넘지 못합니다. 용융지를 보고 속도와 위빙을 바꾸는 공정 기술, 위빙 끝에서 머무는 것 같은 숙련공의 손기술은 배우지 않습니다. 실기에서 적응하는 길은 개입 데이터로 배우는 잔차 모델뿐이고, 그마저 사람 권한 축(높이·좌우·토치 각도)만 고칩니다. 진행 속도와 위빙은 규칙 전문가 값 그대로라, 틈새 → 위빙·속도 규칙을 실기 전에 WPS 값으로 바꿔야 합니다.
- **위험:** 시뮬 오차 분포와 depth 단면 센서 모델이 실제와 다르면 엉뚱한 범위를 배웁니다. 오차 범위는 실측으로 맞추고, 구현은 오차별 단독 검증으로 확인합니다([모재 오차 모델링 계획](https://claude.ai/artifact/UftNfNDdFX5SXsranrBDFk), [sim_errors/README.md](../sim_errors/README.md)).
- **바꿀 때:** 실기 시연 미세조정을 넣는 방법은 아래 "보류한 기능"에 있습니다. 카메라 영상을 입력에 넣으려면 배경·조명 도메인 랜덤화가 필요합니다. 개입 데이터로 기본 정책도 고치려면 "개입 데이터 활용"의 대안(같은 모델 재학습)으로 바꿉니다.

## 사람 개입과 텔레옵

### 사람 개입: 공유 제어

- **채택:** 모델은 개입 중에도 멈추지 않고 추론을 이어 가며, 사람 보정은 이음매 좌표계에서 모델 보정에 더합니다.
- **대안:** 넘겨받기. 클러치를 누르면 정책 명령을 끊고 사람이 조종하며, 복귀할 때 남은 행동 묶음을 버리고 새로 추론합니다.
- **이유:** 사람이 조작하는 동안에도 모델이 "생각"하며 반응하기를 원했습니다. 넘겨받기에서 ACT는 기억이 없어 개입 중 추론이 사실상 정지와 같습니다. 가장 가까운 연구인 CR-DAgger(NeurIPS 2025)에서 보정을 더하는 방식이 넘겨받기보다 성공률이 약 45% 높았습니다.
- **바꿀 때:** 넘겨받기로 가면 모든 축의 사람 권한을 100%로 두는 것과 같아서 구조는 그대로 쓸 수 있습니다. 다만 잔차 모델의 학습 데이터(사람 델타)는 얻을 수 없게 됩니다.

### 개입 데이터 활용: 작은 잔차 모델

- **채택:** 보정 정책은 시뮬 데이터로 학습한 뒤 고정하고, 공유 제어 중 모인 사람 보정(델타)으로 작은 잔차 모델을 학습합니다.
- **대안:** 개입 데이터를 시연에 합쳐 같은 모델을 다시 학습(HG-DAgger 방식, 정답은 모델 보정 + 사람 보정 합계). 두 방식을 모두 구현해 시뮬에서 비교.
- **이유:** CR-DAgger에서 사람 보정만 배우는 작은 잔차 모델이 같은 모델 재학습보다 훨씬 나았고, 보정 에피소드 50\~100개로 충분했습니다. 다만 접촉 작업 결과라 용접에서는 검증되지 않았습니다.
- **바꿀 때:** 같은 모델 재학습으로 가면 로봇 목표에서 잔차 항이 빠지고, 정답을 실행된 합계로 바꿉니다. 개입 구간 비중을 높이고 개입 직전 약 2초를 빼는 규칙(Sirius)은 두 방식 모두 적용됩니다.

### 축별 권한과 놓은 뒤 처리

- **채택:** 높이·좌우·토치 각도는 사람, 진행과 위빙은 모델이 맡습니다. 클러치를 놓으면 사람 보정을 오프셋으로 유지합니다.
- **대안:** 다른 축 배분(예: 진행 속도도 사람). 놓은 뒤 사람 보정을 서서히 줄이기.
- **이유:** 숙련공이 주로 고치는 것은 높이와 각도이고, 진행과 위빙을 모델이 이어 가야 공유 제어의 의미가 있습니다. 오프셋을 유지하면 토치를 2 mm 올린 의도가 놓은 뒤에도 남습니다.
- **바꿀 때:** 권한 비율과 감쇠 속도는 설정값이라 구조 변경 없이 바꿀 수 있습니다. 감쇠는 시뮬에서 비교해 보고 정하면 됩니다.

### 제어 주체 중재: 클러치와 축별 권한 규칙

- **채택:** 사람과 모델 중 누가 조종할지는 클러치와 축별 권한 규칙이 정합니다.
- **대안:** Jev가 사람 입력, 정책 출력, 이음매 감지 결과를 보고 "사람 우선 / 모델 우선 / 블렌딩 / 정지" 중 하나를 고름.
- **이유:** 규칙으로 두면 사람이 누른 클러치가 항상 그대로 통합니다. Jev는 판단에 0.1\~0.6초가 걸려 즉각적인 주도권 전환에 맞지 않습니다.
- **바꿀 때:** Jev에 중재를 맡기려면 Jev 연결(상태 요약과 선택지)을 새로 만들고 중재 모드를 선택지로 넣으며, 어떤 경우에도 클러치가 우선하도록 해야 합니다.

### 텔레옵 방식: TCP(토치 끝)

- **채택:** 리더 손끝의 움직임을 토치 끝이 따라가는 TCP 방식입니다.
- **대안:** 관절 방식. opti3 팔 모양이 리더 팔 모양을 따라갑니다.
- **비교:** 관절 방식은 IK가 없어 도달 범위 경계의 정지가 없고 단순합니다. 대신 opti3 팔이 약 2.5배 길어 리더 10 cm가 토치 약 25 cm가 되고, 토치 길이와 손목 구조가 달라 토치 각도가 정확히 맞지 않으며, 클러치로 리더를 다시 잡을 수 없습니다.
- **이유:** 용접은 곧은 선을 일정한 토치 각도로 따라가야 하고, 이음매 좌표 보정과 사람 보정 더하기가 모두 TCP 변화량을 전제로 합니다.
- **바꿀 때:** 관절 방식에서는 사람 보정을 FK로 토치 변화량으로 바꿔 이음매 좌표계에 넣어야 하고, 클러치 ON 때 opti3가 리더 자세까지 천천히 이동하는 단계가 필요합니다.

## 미정 장치, 보류한 기능, 참고 자료

### 보류한 기능

지금 구조에는 넣지 않았지만, 구조를 바꾸지 않고 나중에 붙일 수 있는 기능입니다.

- **사람 동작 다듬기:** Diffusion Policy처럼 노이즈 제거 방식의 모델이라면, 사람 동작에 노이즈를 일부 섞고 모델이 걷어 내게 해 사람 의도를 숙련 동작으로 다듬을 수 있습니다 ([Yoneda et al., RSS 2023](https://arxiv.org/abs/2302.12244)). 정책 모델을 정한 뒤에 검토합니다.
- **리더 햅틱 가이드:** 리더의 Feetech 서보 토크로 모델이 가려는 쪽을 약하게 알려 줍니다. 붙이더라도 로봇 정지는 모델과 어긋났다는 이유가 아니라 안전 기준으로만 합니다.
- **검출 기반 자동 시작:** 작업 시작 항목의 "바꿀 때"를 참고하세요.
- **실기 시연 미세조정:** 시뮬로 학습한 보정 정책을 실기 아크 텔레옵 시연으로 미세조정해, 용융지를 보고 속도·위빙을 바꾸는 공정 기술과 숙련공의 손기술(위빙 끝에서 머무는 동작 등)을 더합니다. 접근부터 후퇴까지 전체 에피소드를 텔레옵으로 녹화하고 시점별 단계 라벨, 직선/위빙 모드, 아크 ON/OFF 시점을 기록합니다. 용접 단계 구간을 이음매 기준 보정값으로 바꿔 시뮬 데이터를 일부 섞어 미세조정한 뒤 다시 고정합니다. 섞지 않으면 기하 보정을 잊기 쉽습니다. 정책 입력은 그대로 두고, 잔차 모델은 새 보정 정책 위에서 다시 학습합니다. 실기 아크 환경이 갖춰지면 검토합니다.

### 실제 로봇으로 옮길 때 정할 장치

- **클러치와 시작 트리거 장치:** 풋페달, 리더 손잡이 버튼, PLC 신호 중에서 고릅니다. 시뮬에서는 Enter 키를 클러치로 씁니다.
- **실제 아크 용접의 이음매 센서:** 실기 검증은 아크 없는 시연이라 손목 depth 카메라로 충분하지만, 실제 아크 용접에서는 depth 카메라가 아크 빛과 연기에 가려집니다. 그때는 레이저 라인 센서나 아크 센싱으로 바꿉니다(위 "용접 중 이음매 관측").
